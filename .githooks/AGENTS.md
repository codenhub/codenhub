# Agent instructions: `.githooks/`

## Traps

- An edited hook does not run when tried from a worktree the Claude desktop app created; the main checkout's copy runs instead. The app writes an absolute `core.hooksPath` pointing at the main checkout into the worktree's `config.worktree`, which `git config --show-origin --get-all core.hooksPath` shows. Prefer `git -c core.hooksPath="$(pwd)/.githooks" <command>` to exercise the worktree's copy. Held on git 2.53.0 for Windows with the desktop app of October 2026: a push of `claude/agent-branch-naming-03bee5` went through while the worktree's `pre-push` already refused that name.
- A hook killed by a signal counts as passed: git proceeds with the commit or push as if the hook had succeeded. The usual trigger is SIGPIPE, when git's output is piped into something that stops reading early, such as `git commit ... 2>&1 | head -1`; a hook writes its message exactly when it rejects, so the closed pipe kills it at that moment. Each hook sets `trap "" PIPE` so a failed write is an ordinary error and the hook's own exit status stands. That covers SIGPIPE only: a hook killed by SIGTERM or SIGKILL, as a timeout or an external kill does, still passes. Held on git 2.53.0 for Windows: a `commit-msg` that ran `kill -TERM $$` or `kill -KILL $$` before `exit 1` let the commit through with git exiting 0, and `git commit -m "Add hooks" 2>&1 | head -1` committed until the trap was added. Linux and macOS were not checked. See codenhub/codenhub#229.
