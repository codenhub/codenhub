# 0.4.0

## Added

- Motion classes that move the whole icon: `ic-anim-spin`, `ic-anim-pulse`, `ic-anim-beat`, `ic-anim-bounce`, and `ic-anim-wiggle`. They run for as long as the class is present, `--ic-anim-duration` sets their speed, `--ic-anim-iterations` their repeat count, and `prefers-reduced-motion: reduce` turns them off. In Tailwind they are utilities, so variants such as `group-hover:ic-anim-spin` work too. They move the whole glyph: the artwork is a CSS mask, so parts of an icon cannot be animated from the page. See Concepts, Motion.
- `ic-on-hover` plays an icon's motion, from a motion class or from its animated artwork, while its trigger is hovered or has visible focus, and holds it at rest otherwise: upright, or on its static artwork. The trigger is the icon, its parent, or any ancestor marked `ic-trigger`, such as a card. Each hover plays from the start, once by default; `--ic-anim-iterations: infinite` keeps it moving while hovered.
- `@codenhub/icons/play`, an opt-in entry point with no icon data. `playIcon(element)` plays an icon from the start, for feedback on an event such as a copy or a like. `bindIconPlayback()` replays one-shot artwork, such as a Line MD draw-in, on every hover rather than the first only, which CSS cannot do because a browser does not restart an image it has already shown. See JavaScript API, Playing icons from code.
- `line-md`, a core family of 1,222 animated, stroke-based icons such as `ic-line-md-loading-loop` and `ic-line-md-heart`, from [Line MD](https://github.com/cyberalien/line-md) 3.0.5 under MIT, and its stylesheet `@codenhub/icons/line-md`. Icons named `-loop` animate continuously; the others draw in or morph once. Under `prefers-reduced-motion: reduce`, CSS masks switch to the upstream static artwork, in the family stylesheet, Tailwind, and CSS mode in Vite and PostCSS; inline SVG keeps the animated artwork, since CSS cannot stop it. Tested in Chrome only; Firefox and Safari are untested. See Concepts, Animated families.
- `svg-spinners`, a core family of 46 loading indicators such as `ic-svg-spinners-90-ring`, from [SVG Spinners](https://github.com/n3r4zzurr0/svg-spinners) under MIT, and its stylesheet `@codenhub/icons/svg-spinners`. They keep animating under reduced motion, because the motion conveys loading.
- `--ic-static-mask` carries an animated icon's static artwork, next to `--ic-mask`. `IconData.staticBody` and `ResolvedIcon.staticBody` carry the same artwork as markup.

## Changed

- **Breaking.** The `<svg>` a `virtual:@codenhub/icons/<family>/<name>` module exports carries the icon's qualified class, such as `class="ic-lucide-tag"`, so the base rules size and color it from `--ic-size`, `--ic-color`, and the `ic-xs`–`ic-xl` classes, as they do an `<svg>` that svg mode inlines. Code that adds its own `class` attribute to that markup as a string now produces a second one; add to the existing attribute, or use `classList`. [codenhub/codenhub#452](https://github.com/codenhub/codenhub/issues/452)
- **Breaking.** `anim` is reserved for the motion utilities, as `xs`–`xl` are for size. A class `ic-anim` or `ic-anim-*` never resolves as an icon, including from a family adopted with `adoptIconifySet`, and the generator refuses a family prefix or icon named that way, or leaves the icon out of a brand family. The exact names `on-hover` and `trigger` are reserved the same way. No icon in a shipped family is affected.
- **Breaking.** A relative `content` entry for the Vite plugin is read from Vite's `root` instead of the working directory, so `./src/**/*.astro` finds the app's files when the build runs from a monorepo root or with `vite --root`. A project whose `root` differs from the directory it builds from and whose entries were written relative to that directory needs them rewritten relative to `root`, or made absolute. The PostCSS plugin, which has no root, still reads from the working directory.
- The package is larger: the tarball unpacks to about 72 MB, up from 67 MB, and the full `line-md` stylesheet is about 3 MB, a third of it the static fallback. CSS from the plugins still carries only the icons a project uses.

## Fixed

- In `mode: "svg"`, an icon tag written inside a string in an `.astro` frontmatter broke `astro build` with a parse error. Astro compiled the file before the plugin's transform ran, so the `<svg>` landed unescaped in a string the compiler had re-quoted. The transform now runs ahead of other plugins' ordinary transforms, Astro's compiler among them; a plugin that also orders its transform `"pre"` and is listed earlier still runs first. [codenhub/codenhub#451](https://github.com/codenhub/codenhub/issues/451)
- In `mode: "svg"`, an icon inlined as a React JSX element kept HTML attribute names such as `stroke-width`, so React logged an invalid DOM property warning for every stroked icon in development. In a project that uses `@vitejs/plugin-react` or `@vitejs/plugin-react-swc`, hyphenated attributes in a JSX element are now written as React names them, such as `strokeWidth` and `fillRule`, and a `style` becomes an object. Solid, Preact, and Vue JSX write attribute names into HTML as given, so there the hyphenated names and the `style` string stay. An icon tag inside a string, as one assigned to `innerHTML`, keeps the hyphenated names the HTML parser reads. [codenhub/codenhub#561](https://github.com/codenhub/codenhub/issues/561)
- In `mode: "svg"`, a quote in JSX text, such as the apostrophe in `<p>Don't</p>`, made the transform treat the next icon tag as part of a string and escape its markup, so the page showed the escaped `<svg>`. A string now ends at its line, and a quote opens one only where an expression can start.
- In `mode: "svg"`, an icon tag with a `>` inside an attribute, such as `onClick={() => a > b}` or `title="a > b"`, was cut at that `>` and left broken markup. The whole tag is now replaced.
- In `mode: "svg"`, a file with many unclosed `<i` tags took over a minute to transform. It now takes milliseconds.
- In `mode: "svg"`, a quote in a `.vue` or `.svelte` template, which the framework reads as markup, made the next icon inlined inside it be escaped as if it were in a JavaScript string. Templates and `<script>` blocks are now read separately.
- In `mode: "svg"` during `vite dev`, an icon removed from a file kept its family's CSS and its unresolved-class warning until the server restarted. Each file now forgets what it used when it is transformed again or deleted.
- With the Tailwind plugin, a variant on a motion utility, such as `hover:ic-anim-spin`, lost its animation in a production build, because Tailwind's optimizer drops a rule that nests `@keyframes`. The keyframes are now declared once at the top level.
- `playIcon` and `bindIconPlayback` threw in jsdom, which has neither `matchMedia` nor `SVGSVGElement.setCurrentTime`. Without `matchMedia`, an icon is not played, since the page cannot say whether motion is reduced; an inline `<svg>` without `setCurrentTime` restarts its glyph motion only.
- `generateFamilyCss` with `bareNames` wrote a bare selector for an icon named like a motion utility, such as `spin`, so `class="ic-anim-spin"` painted that icon. Such an icon now keeps only its qualified selector.
- An `ic-on-hover` icon that itself had keyboard focus stayed at rest, though its focused parent or `ic-trigger` played it. The icon now plays when it has `:focus-visible` too, in CSS as `bindIconPlayback` already did.
- An icon name inherited by every JavaScript object, such as `ic-lucide-constructor`, resolved as an empty icon. Only a family's own icons and aliases resolve now.
