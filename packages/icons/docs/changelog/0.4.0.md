# 0.4.0

## Added

- Motion classes that move the whole icon: `ic-anim-spin`, `ic-anim-pulse`, `ic-anim-beat`, `ic-anim-bounce`, and `ic-anim-wiggle`. They run for as long as the class is present, `--ic-anim-duration` sets their speed, `--ic-anim-iterations` their repeat count, and `prefers-reduced-motion: reduce` turns them off. In Tailwind they are utilities, so variants such as `group-hover:ic-anim-spin` work too. They move the whole glyph: the artwork is a CSS mask, so parts of an icon cannot be animated from the page. See Concepts, Motion.
- `ic-on-hover` plays an icon's motion, from a motion class or from its animated artwork, while its trigger is hovered or has visible focus, and holds it at rest otherwise: upright, or on its static artwork. The trigger is the icon, its parent, or any ancestor marked `ic-trigger`, such as a card. Each hover plays from the start, once by default; `--ic-anim-iterations: infinite` keeps it moving while hovered.
- `@codenhub/icons/play`, an opt-in entry point with no icon data. `playIcon(element)` plays an icon from the start, for feedback on an event such as a copy or a like. `bindIconPlayback()` replays one-shot artwork, such as a Line MD draw-in, on every hover rather than the first only, which CSS cannot do because a browser does not restart an image it has already shown. See JavaScript API, Playing icons from code.
- `line-md`, a core family of 1,222 animated, stroke-based icons such as `ic-line-md-loading-loop` and `ic-line-md-heart`, from [Line MD](https://github.com/cyberalien/line-md) 3.0.5 under MIT, and its stylesheet `@codenhub/icons/line-md`. Icons named `-loop` animate continuously; the others draw in or morph once. Under `prefers-reduced-motion: reduce`, CSS masks switch to the upstream static artwork, in the family stylesheet, Tailwind, and CSS mode in Vite and PostCSS; inline SVG keeps the animated artwork, since CSS cannot stop it. Tested in Chrome only; Firefox and Safari are untested. See Concepts, Animated families.
- `svg-spinners`, a core family of 46 loading indicators such as `ic-svg-spinners-90-ring`, from [SVG Spinners](https://github.com/n3r4zzurr0/svg-spinners) under MIT, and its stylesheet `@codenhub/icons/svg-spinners`. They keep animating under reduced motion, because the motion conveys loading.
- `--ic-static-mask` carries an animated icon's static artwork, next to `--ic-mask`. `IconData.staticBody` and `ResolvedIcon.staticBody` carry the same artwork as markup.

## Changed

- **Breaking.** The `<svg>` a `virtual:@codenhub/icons/<family>/<name>` module exports carries the icon's qualified class, such as `class="ic-lucide-tag"`, so the base rules size and color it from `--ic-size`, `--ic-color`, and the `ic-xs`–`ic-xl` classes, as they do an `<svg>` that svg mode inlines. Code that adds its own `class` attribute to that markup as a string now produces a second one; add to the existing attribute, or use `classList`. [codenhub/codenhub#452](https://github.com/codenhub/codenhub/issues/452)
- **Breaking.** `anim` is reserved for the motion utilities, as `xs`–`xl` are for size. A class `ic-anim` or `ic-anim-*` never resolves as an icon, including from a family adopted with `adoptIconifySet`, and the generator refuses a family prefix or icon named that way, or leaves the icon out of a brand family. The exact names `on-hover` and `trigger` are reserved the same way. No icon in a shipped family is affected.
- The package is larger: the tarball unpacks to about 72 MB, up from 67 MB, and the full `line-md` stylesheet is about 3 MB, a third of it the static fallback. CSS from the plugins still carries only the icons a project uses.
