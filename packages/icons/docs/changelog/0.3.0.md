# 0.3.0

## Added

- `simple-icons`, a brand family of 3,254 logos such as `ic-simple-icons-github` and `ic-simple-icons-npm`, from [Simple Icons](https://simpleicons.org). It is opt-in: `@codenhub/icons/tw` never resolves it, and the other methods resolve it only when named, and its stylesheet carries only qualified names, so it never takes a bare name such as `ic-x` from another family. Icons that Simple Icons records under a license of their own are left out unless that license is one that places no obligation, CC0 or Unlicense. The marks are trademarks of their owners; see Licensing.
- `logos`, a brand family of 2,016 full-color logos such as `ic-logos-google` and `ic-logos-slack-icon`, from [gilbarbara/logos](https://github.com/gilbarbara/logos) under CC0-1.0, and its stylesheet `@codenhub/icons/logos`. It is opt-in in the same way as `simple-icons`, and its stylesheet likewise carries only qualified names. Multicolor marks keep their colors and gradients in CSS, inline SVG, and a Vite build, including under a Content Security Policy that blocks inline styles. Variants such as `-icon` and `-dark` are separate names. Two upstream files whose markup cannot render self-contained, `sinatra` and `waffle-icon`, are left out. About 80% of the logos are not square, mostly wordmarks, and render small in the square icon box. Inlined as SVG, two copies of one logo share its gradient, mask, and clip-path ids, so a copy shown after one hidden with `display: none` renders blank; see Vite, Inline SVG mode. [codenhub/codenhub#326](https://github.com/codenhub/codenhub/issues/326)
- Brand icons render in their brand color by default. `--ic-color`, set on an icon or any ancestor, overrides it: `:root { --ic-color: currentColor; }` makes every icon monochrome, and a per-icon value recolors one, turning a full-color logo into a one-color silhouette. In inline SVG mode under a Content Security Policy that blocks `style` attributes, a brand icon keeps its brand colors and `--ic-color` no longer reaches it. Several brand colors are near-black and need an override in a dark theme. See Concepts, Color.
- `IconData.color` and `ResolvedIcon.color` carry an icon's own color. `RenderSvgOptions.prefix` sets the class prefix whose `--<prefix>-color` overrides it.
- A Troubleshooting page, guidance on finding icon names, accessibility guidance, and a generated API reference.

## Changed

- **Breaking.** Node.js 24 or newer is required, up from 22. 24 is the only version line CI runs.
- **Breaking.** `escapeSelectorClass`, `generateIconCss`, `GenerateIconCssOptions`, and `renderSuppressedAttributionWarning` are no longer exported. They were the plugins' internals; `generateIconSetCss` and `generateFamilyCss` produce complete rules.
- **Breaking.** The base rules paint an icon with the `background` shorthand, `var(--ic-color, var(--ic-brand-paint, var(--ic-brand-color, currentColor)))`, instead of `background-color`, so a full-color logo can paint its own artwork. An element carrying `.ic` no longer keeps a `background-image` of its own. Nothing else changes for an icon without a color of its own.
- A Vite build in CSS mode with HTML entries links the generated stylesheet as a hashed CSS asset instead of inlining a `<style>` tag. A build without HTML entries, such as a library build, emits no stylesheet.
- **Breaking.** `drive_fusiontable` is gone from all six Material Symbols families, removed upstream in `@material-symbols/svg-400` 0.48.0. Material Symbols now has 3,929 icons per family, up from 3,899, and Lucide 2,159, up from 2,034 (`lucide-static` 1.59.0).
- The package is larger: the tarball unpacks to about 66 MB, up from 43 MB, mostly the `logos` artwork. Builds with the Tailwind plugin use more memory, since it loads every family. CSS from the plugins still carries only the icons a project uses.

## Fixed

- Material Symbols and Simple Icons icons rendered black when inlined through `mode: "svg"`, `renderSvg`, or a `virtual:@codenhub/icons/…` module, ignoring `color` and `--ic-color`. Their artwork sets no fill of its own; the rendered `<svg>` now carries `fill="currentColor"`.
- Every icon rendered blank in a production Vite build served with a Content Security Policy that does not allow inline styles. [codenhub/codenhub#318](https://github.com/codenhub/codenhub/issues/318)
- Each family's `LICENSE` and `ATTRIBUTION.md` were missing from the published package, though the notices and the `attribution: "off"` warning point to them. [codenhub/codenhub#323](https://github.com/codenhub/codenhub/issues/323)
- An icon inlined by `mode: "svg"` lost its icon class, so `--ic-size`, `--ic-color`, and the size classes did not reach it.
- `mode: "svg"` rewrote `<i data-class="ic-…">` as if it were `class`.
- The PostCSS plugin's generated rules carried no source file, so Vite warned on every build.
- Icon class names holding characters other than `.` and `/`, possible with a custom family or prefix, produced invalid selectors. They are now escaped as `CSS.escape` would.
- `mode: "svg"` broke a build, or changed the string, when an inlined icon landed in a string literal and its artwork held a backslash or a line break; when the tag sat in a double-quoted string inside a template literal's `${…}`; or, in an `.astro` template, when a `<script>` closed with a space before `>`.
- The codenhub.dev package list linked the demo to `icons.codenhub.dev` instead of `demo.codenhub.dev/icons/`.
