# 0.4.0

## Changed

- `document.documentElement` now always carries `theme-light` or `theme-dark`, following the active theme's `colorScheme`, whatever the theme is named and whatever `className` is set to. A light theme named `paper` gets `theme-paper theme-light`, so stylesheets keyed on `.theme-light` and `.theme-dark`, such as the `dark:` variant of `@codenhub/styles`, match it without a workaround. The pre-paint script applies the same class. ([#627](https://github.com/codenhub/codenhub/issues/627))
- The manager now owns `theme-light` and `theme-dark` on the root element: it adds and removes them on every change, and `destroy({ revertDom: true })` removes them even if the page added them itself. A page that sets either class by hand, or a stylesheet that expects only the theme's own class to be present, should drop that code when upgrading.
