# 0.4.1

## Fixed

- While the browser blocks `localStorage`, `theme.preference` and `theme.followsSystem` now report the choice made on this page with `set()` or `toggle()`, until `clearPreference()` or `destroy()`, instead of staying `null` and `false`. The manager already applied that choice, so a menu that shows "Auto" while `preference` is `null` took a fixed pick for "Auto" and switched the page back to the operating system's scheme. When storage can be read but not written, as with a full quota, they still report the previously saved choice. ([#669](https://github.com/codenhub/codenhub/issues/669))
