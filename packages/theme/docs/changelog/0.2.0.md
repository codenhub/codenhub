# 0.2.0

## Added

- Theme names are inferred from the keys of `themes`, so `defaultTheme`, `systemTheme`, `pairedTheme`, and `set()` reject unconfigured names at compile time.
- `theme.name`, `theme.preference`, and `theme.system` getters read the active name, the stored preference, and the theme the OS preference maps to.
- `setTokens(tokens)` replaces the runtime token overrides; pass `{}` to remove them. Changes it makes report `source: "setTokens"`.
- `readTokens()` returns every token, completed with computed CSS values at the time of the call.
- Changes made in another tab report `source: "storage"`, so code that mirrors the preference elsewhere can tell them from local changes.
- The `ThemeChangeEvent` type types the `themechange` window event, whose `detail` was untyped.

## Changed

- `themes` is an object keyed by theme name instead of an array: `{ light: { colorScheme: "light" } }` replaces `[{ name: "light", colorScheme: "light" }]`.
- Methods are bound to their manager, so `theme.toggle` and `theme.subscribe` can be passed as callbacks directly.
- `get()` returns the same frozen object until the next change and never reads the DOM, so it can serve as a store snapshot such as `useSyncExternalStore(theme.subscribe, theme.get)`. Its `tokens` holds static and runtime tokens only; call `readTokens()` for tokens defined only in CSS.
- `isTailwindCss` is renamed `darkClass`, and `shouldApplyClass` is renamed `className`.
- `Theme`, `ThemeOptions`, and the other generic types take the theme name union as their first type parameter, before the token schema.
- When another tab sets, clears, or invalidates the preference, every tab re-resolves its theme and notifies, even when the active theme stays the same, so a settings screen sees the preference change.
- Listener errors are logged as `[theme] Error in theme change listener:`, matching the package's other messages.
- A storage operation that fails is logged the first time it fails for a manager, not on every call, so a page with blocked storage no longer logs an error each time `theme.preference` is read.
- A theme or runtime token value that is not a string, a finite number, or `undefined` throws; a number is written as its string, which `get().tokens` now reports too.
- A runtime token set to `undefined` counts as omitted, so `setTokens({ primary: undefined })` keeps the theme's static `primary` instead of removing it.
- `createTheme()` throws `Theme options must be an object.` for options such as `null`, instead of an unrelated `TypeError`.

## Removed

- The standalone `getPrePaintScript(options)` export. Use `createTheme(options).getPrePaintScript()`, which is safe to call on the server.
- The `LIGHT_THEME` and `DARK_THEME` exports; the built-in themes are the default `themes` value.
- `getStored()`, `getSystem()`, and `get({ skipComputed })`; use `preference`, `system`, and `get()` with `readTokens()`.
- The `tokens` parameter of `init()`, `set()`, and `toggle()`; use `setTokens()`.

## Fixed

- Calling `theme.toggle` as an event listener no longer throws, and no longer treats the event as token overrides.
- A snapshot taken before a theme change no longer reports the new theme's computed tokens under the old theme's name.
- The pre-paint script applies the OS theme when `localStorage` access throws, applies `defaultTheme` when `matchMedia` is missing as `init()` does, and replaces a server-rendered theme class instead of adding a second one.
- `localStorage.clear()` in another tab now applies the system theme.
- An option set to `undefined`, such as `storageKey: props.storageKey` forwarded by a wrapper, uses its default instead of making `createTheme()` throw.
- A token named after an `Object.prototype` member, such as `constructor`, is handled as an ordinary token instead of writing the inherited function to the DOM.
- A `systemTheme` that is not an object, or a `darkClass` that is not a boolean, throws from `createTheme()` instead of being silently accepted.
- The pre-paint script falls back as for an unknown name when the stored value is an `Object.prototype` property such as `toString`, and applies a configured theme named `__proto__`. ([#345](https://github.com/codenhub/codenhub/issues/345))
- Invalid options, such as a `defaultTheme` naming an unconfigured theme, throw from `createTheme()` instead of reaching the page through the pre-paint script. ([#364](https://github.com/codenhub/codenhub/issues/364))

- A subscriber or `themechange` listener that changes the theme, such as by calling `set()` or `setTokens()`, no longer leaves the subscribers and `themechange` listeners after it with the superseded change.
- When storing fails, an explicit choice made with `set()` or `toggle()`, before or after `init()`, is no longer overridden by `init()` or the next OS color-scheme change.
- The `themechange` event is built with the window's own `CustomEvent`, so `init()` and other changes no longer throw when the global `CustomEvent` belongs to another realm, as in a hand-built jsdom setup.

## Security

- Theme names, option values, and token values can no longer close the inline `<script>` element or open an HTML comment in the pre-paint script.
