# 0.4.0

## Added

- A registry entry can be `{ code }`, an `ErrorCodeAlias`, instead of carrying words. A match on it takes the named code's `message`, `messageKey`, `source`, and `isRetryable`, and keeps the `type` the match earns, so `names.add("NotAllowedError", { code: "workspace.permissionDenied" })` and a pattern for the desktop's `(os error 5)` report the same failure with the same `code`. A platform layer can recognize a failure without writing user-facing text. The code is looked up when an error is created, so aliases and the words they name can come from registries merged in any order. An alias whose code is missing, or is itself an alias, matches nothing and matching moves on, so no raw text is shown. ([#676](https://github.com/codenhub/codenhub/issues/676))
- The documentation is available in Brazilian Portuguese and Spanish, and the English pages are rewritten as one reading path from setup to recipes.

## Changed

- **Breaking.** The package requires Node.js 26 or newer, where it declared 24. Browser, worker, and edge runtimes are unaffected. ([#553](https://github.com/codenhub/codenhub/issues/553))
- **Breaking, TypeScript only.** A registry's `get` and `values` return `ErrorMapping`, which is `ErrorFeedback | ErrorCodeAlias`, so `registry.codes.get(id)?.message` is typed `string | undefined`. A worded entry typed with a `code` field, such as `{ code: string; message: string }`, no longer type-checks, though it still registers at runtime with its `code` ignored, as before. Where code reads an entry's words, check `mapping.message !== undefined` first. `ErrorPrefixDefinition` and `ErrorPatternDefinition` are now unions too, so an interface can no longer extend them; write an intersection instead, such as `type MyPrefix = ErrorPrefixDefinition & { note: string }`.
- An alias with a `messageKey`, `source`, or `isRetryable` beside its `code` throws `TypeError` when it is added, since the words and flags come from the code it names.
- An error matched through a pattern alias carries its `code` across `toJSON()` and `appErrorFromJSON`, which used to reject a `code` on a `"heuristic"` error.

## Fixed

- `AppErrorBoundary` no longer resets when the `resetKeys` change is itself what made a child throw. It rendered the child again in the same update and caught a second throw, so `onReset` fired with nothing to reset and `onError` reported one failure twice. A key change now resets only an error that was already on screen.
