# 0.3.0

## Added

- `attempt` and `attemptAsync` convert throwing code into a `Result` without a hand-rolled `try`/`catch`, which was the only remaining way to reach `err()` from a throwing boundary. Both validate their options before running the callback.
- A generated API reference ships with the package, covering every `exports` subpath.
- A Node.js preset at `@codenhub/error/registries/node` classifies network failures from sockets, DNS, and the built-in `fetch`, such as `ECONNREFUSED`, `ENOTFOUND`, and `UND_ERR_CONNECT_TIMEOUT`. A failed `fetch` on Node.js used to resolve to an unknown error under every built-in preset.
- `AppError.code` holds the registered code that classified the error, or the registered name when no code matched, and `toJSON()` includes it. Consumers can branch on a specific failure without comparing message text or a translation key.
- Entries of an `errors` list, as on `AggregateError`, are classified. The first ten are inspected.
- A `default` export condition, so CommonJS can `require()` the package on runtimes that support requiring ES modules.

## Changed

- **Breaking.** The package requires Node.js 24 or newer, where it declared 22. CI had only ever run it on 24, so the 22 claim was untested; it now names the line CI runs. Browser, worker and edge runtimes are unaffected. ([#203](https://github.com/codenhub/codenhub/issues/203))
- **Breaking.** Strings are classified against the registry at every wrapper depth. Previously only a top-level string bypassed matching, so `err("Failed to fetch")` resolved to the generic fallback while `err({ cause: "Failed to fetch" })` resolved through the registry. A message, prefix, or pattern mapping that matches a top-level string passed to `createAppError` or `err()` now produces a known or unexpected result instead of `unknown`. Registry messages are curated and an unmatched string still resolves to the fallback, so nothing raw reaches a consumer either way.
- **Breaking.** `ok` and `err` results are frozen, so code that mutated one now fails.
- **Breaking.** The browser fetch and network pattern uses its own `error.browser.requestFailed` key rather than `error.browser.network`, so no translation key has to cover two different fallback messages. A translation map covering the old key needs the new one.

- **Breaking.** The browser failed-fetch pattern matches only the whole message an engine produces. Text that merely contains `load failed` or `networkerror`, such as `Config load failed`, is no longer classified as a network failure.
- **Breaking.** `attempt` rejects a callback that returns a promise at the type level. Its rejection used to escape inside an `Ok`; use `attemptAsync`.
- A `messageKey` or `source` is any non-empty string. The repository's naming conventions were enforced at runtime, so an application could not register the keys its translation catalog already had.
- Passing options with an already classified `AppError` keeps its classification unless the options find a match of a higher tier. A lone `fallbackMessage`, or the default `maxDepth` written out, used to turn a known error into an unknown one.

## Fixed

- Normalizing a message is linear in its length. A long message with a run of `.`, `!` or `?` inside it took quadratic time, with or without registered mappings: 80 KB took over seven seconds.
- `attempt` and `attemptAsync` reject an out-of-range `maxDepth` before running the callback. It used to surface only when the callback failed, replacing the real failure.
- A `DOMException` is classified by its name; its legacy numeric `code` could match an unrelated registered code.
- Feedback without a message returned by a hand-written registry throws `TypeError` instead of producing an `AppError` with no message.

## Removed

- The internal `createUntrustedAppError` variant, made redundant by classifying strings at every depth.
