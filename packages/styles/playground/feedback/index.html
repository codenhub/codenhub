UI fixtures

Feedback

Everything that reports state back: alerts, badges, progress, skeletons, loaders, and tooltips. Each grid is one row per presentation and one column per intent, a cell with no intent class at all always first -- a curated subset of both axes rather than every combination, sized to read as a reference.

Alerts

Without a presentation an alert is tinted, intent-colored, and softly bordered.

Icon

The package ships no icon of its own. .alert-icon sizes and aligns whatever icon element you drop in as a child -- an inline <svg> , an <img> , or a class from an icon set such as @codenhub/icons -- and .alert 's own gap-3 spaces it from the message with nothing to trigger.

danger and error alias destructive .

Badges

A badge reads the same presentation classes as an alert.

Progress

Presentation reaches the track border and its width; the fill always uses the intent color.

Active

.active shimmers the track behind the fill.

Indeterminate

.indeterminate animates a partial fill and ignores --progress-value .

Skeletons

Presentation changes placeholder fill and edge strength.

Loaders

Presentation changes the loader tile and artwork. With no intent a loader keeps currentColor , so it matches whatever text surrounds it.

Sizes

Animations

A separate axis from intent: each variant swaps the mask, not the color. Under prefers-reduced-motion every one of them falls back to a static mask.

Tooltips

The bubble reads every axis. Its plate is opaque at every presentation, because a transparent tooltip floating over arbitrary content is unreadable, and with no intent it is --color-tooltip rather than a fill of the page's ink. Point at any cell.

Positions

.tooltip is a wrapper around a trigger and a real .tooltip-bubble , shown on hover or focus. data-tooltip-position on the wrapper places the bubble; with no attribute it goes above the trigger.

Any host

.tooltip wraps any element; it composes rather than replaces the trigger's own classes, so a .btn or a .badge keeps its own look and gains a bubble beside it. .tooltip-icon is only the circular chip for a trigger with nothing else to hang the message on.
