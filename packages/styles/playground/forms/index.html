Input types and icons

On .ipt the icon is opt-in through .icon . text and number have no icon to show.

date and datetime-local depend on the engine. Where the native picker button can be hidden they opt themselves in and show the themed calendar in its place; where it cannot, the native button stays and no custom icon is drawn, because two calendar glyphs on one field read as a defect. They show no alignment cells for that reason: the standard cell is the whole supported surface.

Icons are background images rather than masks, because an input has no pseudo-element to mask and masking the input would clip its border, background, and text. A data URI cannot read a custom property, so each icon ships light and dark artwork and the theme re-points an alias. Input icons follow the theme, not the intent.

Overrides

--ipt-icon-src replaces the artwork; .no-icon suppresses the ones native inputs include by default.

Field anatomy

.field stacks the parts; .label names the control, .hint explains it, and .hint.error is destructive helper text.

The other controls

.field wraps any control, not only .ipt . A toggle sits beside its label instead of under it, so it takes a .cluster rather than the field's own stack.
