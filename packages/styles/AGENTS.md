# packages/styles

## Traps

- **`/*/tw` in a CSS comment ends the comment.** The wildcard for the Tailwind paths holds `*/`, so written in a comment of `src/*.css` it closes it, and the rest of the comment is parsed as CSS: on 2026-11-15, under Tailwind 4.3.4, `pnpm generate styles` failed with "Unterminated string" at an apostrophe further down in `reset.rules.css`. Prefer `/<name>/tw` in a stylesheet; Markdown takes either.
- **Tailwind keeps the first `@property` of a name where it stands.** Under Tailwind 4.3.4, `optimizeAst` keeps the first top-level `@property` of each name and drops later ones, without hoisting it; the registrations its own utilities need are appended at the end of the output, and a `@property` nested in a `@utility` is neither moved nor deduplicated. So the nine `--tw-*` registrations `tw/theme.css` ships come out where the consumer imports the theme, and a consumer's own `font-bold` reuses them instead of adding its own. Moved inside a `@utility`, they would ship once per utility that names them. `dist/purge/index.css` is compiled from `tw/`, so `scripts/build-purge.mjs` moves them to the end, where `dist/index.css` has them; `tests/integration/purge.test.ts` fails otherwise. Prefer keeping them top-level in `tw/theme.css`.
- **The registrations in `tw/theme.css` must come before its rules.** Lightning CSS merges two identical adjacent `@media (forced-colors: active)` blocks only when nothing stands between them. A focused `/tw` export that reaches `theme.css` twice, such as `/reset/tw` through `typography.css`, emits its forced-colors block twice, and with the registrations at the end of `tw/theme.css` they sat between the two copies, so the export no longer matched its previous output: measured on 2026-11-15 with Tailwind 4.3.4 and Lightning CSS 1.33. `scripts/build-tw.mjs` places them after the theme's imports. Prefer that position over appending anything to the end of `tw/theme.css` other than `adapter.css`.
