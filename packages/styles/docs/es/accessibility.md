# Accesibilidad

La pantalla de ajustes está construida, y el CSS ha hecho su parte por el camino: cada campo muestra dónde está el foco, un email inválido se vuelve rojo y el spinner se detiene para los usuarios que piden menos movimiento. El resto depende de tu HTML y tu JavaScript. Este paquete da estilo a los estados; no aporta elementos semánticos, atributos ARIA, comportamiento de teclado, gestión del foco, validación ni el momento de los anuncios.

Esta página enumera las dos mitades: lo que aporta el CSS y lo que tu aplicación tiene que añadir.

## Lo que aporta el CSS

### Foco y estado

| Característica                  | Comportamiento                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `:focus-visible`                | Un contorno de foco en cada elemento, dibujado con `--focus-ring`, `--focus-ring-width` y `--focus-ring-offset`. En un componente con un relleno de más de la mitad de intensidad, como un botón `.solid.primary`, una línea de 2px del color de texto del propio componente recorre el interior del anillo, así que el foco sigue visible sobre un relleno del color del anillo, o sobre una superficie de ese color. Un control neutro sobre una superficie sólida, como un botón ghost o un campo en una `.card.solid.primary`, dibuja esa línea en el color de texto de la superficie, porque la superficie también puede ser del color del anillo. Una casilla, un radio, un switch o un `.input-group` ahí dibuja el propio anillo en el color de texto de la superficie. Cualquier otro elemento con foco sobre una superficie sólida, como un enlace, un `<summary>` o una región con `[tabindex]`, dibuja el propio anillo en el color de texto de la superficie, salvo que definas `--focus-ring`. |
| Foco en controles de formulario | `.ipt`, `.textarea` y `.select` dibujan el contorno de foco y cambian su borde al color de la intención. El texto escrito en un campo con una clase de intención usa el tono legible de esa intención, `--intent-strong`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Controles inválidos             | `aria-invalid="true"` en un control de formulario vuelve destructivos su borde y el texto escrito, este último en el tono legible destructivo, tanto sobre la página como sobre una superficie sólida. Un checkbox, un radio o un switch se dibuja exactamente igual que su versión `.destructive`, marca de activado incluida.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Controles deshabilitados        | `disabled`, `aria-disabled="true"`, `data-disabled` y `.disabled` muestran el cursor y la opacidad de deshabilitado, y un control deshabilitado no reacciona al hover, tampoco dentro de un `.input-group`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Campos de solo lectura          | `readonly` en un `.ipt` o un `.textarea` lo deja en reposo sobre el tono de fondo discreto de los campos, `--color-foreground`, sin cambio con el hover, con el texto a plena intensidad y con su anillo de foco, porque un valor de solo lectura todavía puede recibir el foco, seleccionarse y copiarse. No se atenúa. Un `.input-group` cuyo campo es de solo lectura reposa de la misma forma.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Estado abierto                  | `data-state="open"` en un `.tooltip` muestra su burbuja sin hover ni foco, y `data-state="closed"` la oculta aunque tenga hover o foco. Ningún otro componente lee ninguno de los dos.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `<dialog>` nativo               | Un `<dialog>` con `.card`, `.panel`, `.surface` o una clase propia que hace `@apply surface` permanece oculto hasta que se abre, y se abre centrado. Un margen que pongas en el diálogo, como utilidad o en tu propio CSS, sigue sobrescribiendo el centrado, salvo que una utilidad de margen no lo hace cuando tu clase aplica `surface` en CSS plano; consulta [Personalización → Helpers de composición](./usage/customizing.md#helpers-de-composición). Con la [hoja de estilos sin clases](./setup.md#html-sin-clases), un `<dialog>` simple es una `.card.floating` y se comporta igual; con los demás puntos de entrada, un diálogo sin ninguna de estas clases no se toca. Atrapar el foco, cerrar con Escape y dejar inerte la página de detrás es cosa de tu aplicación.                                                                                                                                                                                                                          |

### Contenido visualmente oculto

`.visually-hidden` oculta contenido en pantalla y lo mantiene para los lectores de pantalla, como hace el `<caption>` de la tabla de claves de API en [Contenido y layout → Tablas](./usage/content-and-layout.md#tablas). Viene con las utilidades de layout: en `.`, `./native`, `./tw`, `./native/tw` y `./utilities/tw`. No está en `./components` ni en los puntos de entrada de componentes `./components/tw` y `./*/tw`.

### Límites de los controles

WCAG 1.4.11 pide que el límite de un control que necesitas ver para usarlo tenga un contraste de al menos 3:1 con lo que lo rodea.

| Característica                  | Comportamiento                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Controles de texto en reposo    | A propósito, `.ipt`, `.textarea`, `.select` e `.input-group` reposan con un borde más claro que el completo de su intención, por debajo de 3:1 contra la página (el campo neutro, alrededor de 2.2:1 en ambos temas), para que el hover y el foco tengan un tono más intenso al que cambiar. [Contraste aumentado](#contraste-aumentado) lo dibuja completo, a 3:1 o más.                                                                                                                                                                                                                                                                               |
| Toggles                         | `.checkbox`, `.radio` y `.switch` dibujan su borde completo, porque el borde es lo único que muestra una casilla sin marcar. Sobre una superficie sólida, un toggle sin marcar y sin intent lo dibuja en el color de texto de la superficie, como un switch su perilla, así que ambos miden al menos 3:1 contra la superficie. Con una clase de intent, un toggle sin marcar lo dibuja en el tono fuerte del intent, `--color-<intent>-strong`, así que mide al menos 3:1 contra la página en todos los intents, en ambos temas. Un `.switch` con su propio `.edgeless` es la excepción, más abajo.                                                     |
| `.edgeless` desde un contenedor | Lo ignoran todos los controles de texto y toggles: un contenedor no puede quitar el borde de un campo o toggle que contiene.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `.edgeless` en el control       | `.ipt`, `.textarea`, `.select` y `.switch` pierden su borde y dejan de cumplir 1.4.11 en reposo. `.switch.ghost` conserva su borde incluso entonces, porque sin relleno y sin borde nada mostraría el carril.                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `.checkbox`, `.radio`           | Siempre dibujan su borde, venga `.edgeless` de un contenedor o lo lleven ellos mismos. `.edgeless` en ellos no está soportado.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Carril de progreso              | A propósito, la parte rellena lleva el valor y el carril es un fondo discreto. El carril por defecto, `.soft.edgeless`, mide aproximadamente de 1.1:1 a 1.3:1 frente a la página. La parte rellena mide al menos 3:1 frente a ese carril para todas las intenciones excepto warning en claro (unos 2.7:1) e info en oscuro (unos 2.9:1). [Contraste aumentado](#contraste-aumentado) dibuja la parte rellena en el tono intenso de la intención, a 3:1 o más para todas las intenciones. Donde el propio carril deba cumplir 1.4.11, usa `.ghost.edged` con una clase de intención; consulta [Contornos de progreso](#contornos-de-progreso) más abajo. |

### Contornos de progreso

En un `.progress.ghost.edged`, el carril es la página, y tanto su contorno como la parte rellena se dibujan en el color de la intención. Medido frente a la página, sin estética:

| Intención      | Página clara | Página oscura | Cumple 3:1                                                                    |
| -------------- | ------------ | ------------- | ----------------------------------------------------------------------------- |
| `.primary`     | 18.96:1      | 18.96:1       | Sí                                                                            |
| `.secondary`   | 7.47:1       | 7.63:1        | Sí                                                                            |
| `.success`     | 5.14:1       | 3.69:1        | Sí                                                                            |
| `.warning`     | 3.06:1       | 6.20:1        | Sí                                                                            |
| `.destructive` | 5.80:1       | 3.27:1        | Sí                                                                            |
| `.info`        | 6.17:1       | 3.07:1        | Sí                                                                            |
| Sin intención  | 2.48:1       | 1.91:1        | No: el contorno no cumple, aunque la parte rellena, en el color del texto, sí |

Sin clase de intención, el contorno es el gris discreto de los bordes, `--color-border`. Para que un carril neutro cumpla 1.4.11, dale a la barra una clase de intención, o define `--progress-edge` con un color más intenso, como `var(--color-accent)`, que mide 7.47:1 en una página clara y 7.63:1 en una oscura. Warning en una página clara e info en una oscura superan 3:1 por poco margen, así que vuelve a medir si cambias esos colores.

### Movimiento y transparencia

| Característica                      | Comportamiento                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Movimiento reducido, componentes    | Con `prefers-reduced-motion: reduce`, o `data-motion="reduce"`, cada componente detiene lo que se mueve: el brillo del skeleton y del progreso, el desplazamiento de la barra indeterminada (en su lugar llena su carril, atenuada y quieta), el deslizamiento del relleno del progreso, el crecimiento del tooltip, el desplazamiento de las marcas del radio y del switch, y el movimiento de la pulsación. Lo que cambia de color u opacidad sigue haciendo un fundido: el hover de un botón, la aparición del tooltip y la marca del checkbox. La pulsación en sí sigue ocurriendo, al instante, con el aspecto por defecto, con cada estética y con las clases solo de neobrutalism, chunky tile y cyber, porque es la señal de que un clic se registró.                                                                                                                                                                                                                                                                                                 |
| Sin movimiento, componentes         | Con `data-motion="none"`, los fundidos también terminan al instante.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Movimiento reducido, toda la página | El reset limita todas las demás transiciones de la página al color, la opacidad, la visibilidad, `display` y `overlay`, así que una transformación, un deslizamiento o un cambio de tamaño llega al instante, y un popover o un diálogo que se desvanece al cerrarse todavía puede desvanecerse antes de cerrarse, cuando los tiempos de su `display` y su `overlay` cubren el fundido, como se explica abajo. Cada animación con keyframes termina al instante, también un fundido de entrada, porque una hoja de estilos no puede saber qué anima: también el `::backdrop` de un diálogo y una transición de vista, que cambia la vista antigua por la nueva sin deslizamiento ni fundido cruzado. Una animación ligada al desplazamiento también termina al instante, en su último keyframe, por mucho que se desplace la página, y lo mismo cada transición y animación de `::details-content`, `::file-selector-button` y `::picker(select)`. El desplazamiento suave se detiene. Con `data-motion="none"`, cada transición también termina al instante. |
| Transparencia reducida              | Con `prefers-reduced-transparency: reduce`, y con colores forzados, `.glass`, `.glass-liquid` y `.glass-solo` pierden su desenfoque y su lente y se vuelven opacos.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

La regla de movimiento reducido de cada componente viene con el componente, así que cada punto de entrada que lo incluye respeta el movimiento reducido sin el reset, incluidos `@codenhub/styles/components`, `@codenhub/styles/components/tw` y cada punto de entrada de componente `/*/tw`. Los puntos de entrada completo y native añaden la regla del reset para toda la página.

Una transición que el reset quita no se ejecuta, así que no dispara `transitionend`. Un cajón que se desliza y se elimina a sí mismo con ese evento se queda en la página con movimiento reducido. Comprueba si el elemento todavía tiene una transición que ejecutar antes de esperar el evento, o elimínalo también tras un tiempo de espera. Con `data-motion="none"`, cada transición sigue ejecutándose, durante 0.01ms, así que el evento se dispara.

El reset cambia las propiedades que nombra una transición por su propia lista, en este orden: `opacity`, `display`, `overlay`, `visibility`, `color`, `background-color`, `border-color`, `outline-color`, `text-decoration-color`, `fill` y `stroke`. Tus duraciones, retrasos y funciones de tiempo se quedan como las escribiste, y el navegador las empareja con esa lista por posición, volviendo a empezar desde tu primera entrada cuando tu lista es más corta. Así, `transition: transform 200ms, opacity 1s` funde la opacidad en 200ms, no en 1s, y lo que antes cambiaba al instante ahora también se funde: un color de fondo en 1s y un color de texto en 200ms. En un popover, un diálogo y un `::backdrop`, tu `allow-discrete` es el único valor que no se empareja por posición: `display` y `overlay` siempre lo reciben, en el orden en que los hayas nombrado. Sus duraciones y retrasos sí se emparejan por posición, con tu segunda y tu tercera entrada, así que un popover o un diálogo que se desvanece al cerrarse sigue abierto hasta que termina su fundido solo cuando esas terminan no antes que tu primera, la que recibe `opacity`, contando los retrasos: `transition: opacity 200ms, display 200ms allow-discrete, overlay 200ms allow-discrete` lo cumple, pero `transition: display 1s allow-discrete, opacity 200ms` cierra el popover a los 200ms, a mitad de un fundido que ahora dura 1s. Una sola duración para toda la transición, como se explica abajo, lo mantiene. En cualquier otro elemento tu `transition-behavior` se empareja por posición como lo demás, así que un elemento que ocultas con `display: none` se oculta al instante, salvo que la entrada emparejada con `display`, tu segunda, sea `allow-discrete`.

Una transición pasa por el cambio sin alterarse cuando todas sus propiedades tienen la misma duración, el mismo retraso y la misma función de tiempo, como `transition: opacity 300ms, visibility 300ms`, porque entonces todos los emparejamientos son iguales. Una ocultación escrita con un retraso solo pasa con `opacity` primero: `transition: opacity 300ms, visibility 0s 300ms` se funde y luego se oculta, pero `transition: visibility 0s 300ms, opacity 300ms` empareja `opacity` con la duración cero y el retraso de `visibility`, así que el elemento se queda opaco durante 300ms y luego desaparece de golpe. Dale a `visibility` la duración del fundido en lugar de un retraso: sigue visible hasta que termina su transición, así que se oculta cuando termina el fundido.

Por la misma razón, `transition-property: none` por sí solo no apaga una transición con movimiento reducido: el reset cambia `none` por su lista y mantiene tu duración, así que el color y la opacidad vuelven a fundirse. Eso es exactamente lo que hace `motion-reduce:transition-none` de Tailwind. Pon la duración en cero en su lugar, con `transition: none`, `transition-duration: 0s` o `motion-reduce:duration-0`.

La regla del reset es `!important` dentro de la capa `base`, y un `!important` con capa gana a uno sin capa, así que tu propio `!important` no puede volver a activar una animación. Para mantener una en marcha para los usuarios que piden movimiento reducido, como un spinner de subida que consideres esencial, declárala `!important` en una capa ordenada antes de `base`, tanto con el ajuste del sistema como con el de la app. La primera sentencia `@layer` que lee el navegador fija el orden, así que la tuya va antes del paquete. Una animación ligada al desplazamiento necesita además declarar ahí su `animation-timeline`, porque el reset la devuelve a `auto`:

```css
@layer essential-motion, theme, base, components, utilities;
@import "@codenhub/styles";

@layer essential-motion {
  @media (prefers-reduced-motion: reduce) {
    .upload-spinner {
      animation-duration: 1s !important;
      animation-iteration-count: infinite !important;
    }
  }

  :root:is([data-motion="reduce"], [data-motion="none"]) .upload-spinner {
    animation-duration: 1s !important;
    animation-iteration-count: infinite !important;
  }
}
```

Respetar el movimiento reducido no es todo lo que se pide. El movimiento que sigue en marcha junto al contenido, como un brillo que queda en una tarjeta después de que ha cargado, necesita una forma de detenerlo para todos los usuarios; consulta [Feedback → Animación que no se detiene](./usage/feedback.md#animación-que-no-se-detiene).

### Contraste aumentado

Con `prefers-contrast: more`, o `data-contrast="more"`, los bordes que el paquete dibuja por debajo de 3:1 a propósito se dibujan a 3:1 o más frente a lo que tienen al lado, en ambos temas. El texto, los rellenos sólidos salvo la parte rellena de una barra de progreso, y los anillos de foco ya cumplen sus proporciones y no cambian. `prefers-contrast: less` no se lee.

| Característica      | Comportamiento                                                                                                                                                                                                                                                                           |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Controles de texto  | `.ipt`, `.textarea`, `.select` e `.input-group` reposan con su borde completo. El hover y el foco siguen cambiando su tono, y quedan en 3:1 o más contra la página. Sobre una superficie sólida, ese borde es el color de texto de la superficie. El anillo de foco es el mismo.         |
| Bordes neutros      | `--color-border` toma un gris más intenso, `neutral-600` en claro y `neutral-400` en oscuro, así que el borde de una tarjeta, un divisor, las líneas de una tabla y el borde de un botón o badge neutro cumplen 3:1. Si defines `--color-border` tú mismo, tu color se conserva; mídelo. |
| Bordes de intención | El borde de una intención toma su tono fuerte, `--color-<intent>-strong`, así que `.edged` en un `.alert`, `.panel`, `.badge`, `.kbd`, `.code` o `.pre` `.soft` cumple 3:1 tanto frente a su relleno como frente a la página, en todas las intenciones.                                  |
| Carril de progreso  | El carril dibuja un contorno en su color de borde, que cumple 3:1 con o sin clase de intención, y la parte rellena toma el tono intenso de la intención, que cumple 3:1 frente al carril para todas las intenciones. `.edgeless` en la barra o en un contenedor lo sigue quitando.       |
| Glass               | `.glass`, `.glass-liquid` y `.glass-solo` pierden su desenfoque y su lente y se vuelven opacos, como con la transparencia reducida, y su línea blanca pasa a ser un borde gris.                                                                                                          |
| Chunky tile         | `.chunky-tile` dibuja las piezas y las superficies con el gris más intenso que usan sus controles.                                                                                                                                                                                       |

Lo que quitas sigue quitado: `.edgeless` en un control sigue eliminando su borde, y un `.panel` sigue sin tenerlo salvo que añadas `.edged`.

### Ajustes de la app

Una página no puede cambiar lo que informa una media query, por muy amablemente que se lo pida, así que una app con sus propios ajustes de contraste y movimiento se lo dice al paquete con dos atributos en `<html>`. Cuando un atributo está puesto, decide en lugar del ajuste del sistema. Sin atributo, o con un valor que no está en esta lista, decide el ajuste del sistema, como describen las secciones anteriores.

```html
<html data-contrast="more" data-motion="reduce">
  …
</html>
```

| Atributo        | Valor      | Lo que hace el paquete                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| --------------- | ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `data-contrast` | `more`     | Dibuja los bordes de [contraste aumentado](#contraste-aumentado), pida lo que pida el sistema.                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `data-contrast` | `standard` | Los deja fuera, aunque el sistema pida más contraste.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `data-motion`   | `full`     | Se mueve como sin preferencia, aunque el sistema pida movimiento reducido.                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `data-motion`   | `reduce`   | Hace lo que hace el ajuste de movimiento reducido del sistema: lo que se mueve se detiene, y lo que hace un fundido lo sigue haciendo.                                                                                                                                                                                                                                                                                                                                                                                                        |
| `data-motion`   | `none`     | Termina al instante cada animación y transición, también los fundidos, después del retraso que tenga, así que un tooltip todavía se demora. La duración casi nula mantiene `transitionend` y `animationend` disparándose. Llega a cada elemento, incluso a uno que no declara ninguna transición, así que un cambio de estilo también dispara `transitionend` en él, y una lectura de tamaño justo después del cambio devuelve el valor anterior: lee el layout en el siguiente frame y comprueba el `target` y el `propertyName` del evento. |

Una pantalla de ajustes con "Sistema / Estándar / Más" quita `data-contrast` para Sistema y lo pone para las otras dos, como un [selector de tema](./usage/theming.md#claro-y-oscuro). El movimiento tiene un nivel más, porque el ajuste del sistema tiene solo uno: "Sistema / Todo / Reducido / Ninguno".

- **Solo en `<html>`.** A diferencia de un selector de tema, el atributo no delimita una región: en cualquier otro elemento no hace nada.
- **No dentro de un shadow root.** Las reglas del paquete dentro de un shadow root no pueden ver un atributo en el `<html>` de la página, así que siguen el ajuste del sistema. Una parte sí cruza: cuando la página también carga el paquete, el color de borde neutro se hereda de `<html>`, así que el borde de una card o de un divisor dentro del shadow root sigue `data-contrast` en ambos sentidos, más oscuro con `more` y estándar con `standard`. El borde de un control de texto ahí sigue el ajuste del sistema, como las demás reglas del paquete dentro del shadow root.
- **Las variantes de Tailwind también los siguen.** Con un punto de entrada `/tw`, tus propias utilidades `contrast-more:`, `contrast-less:`, `motion-safe:` y `motion-reduce:` siguen los atributos de la misma forma; consulta [Tailwind → Variantes de contraste y movimiento](./integrating/tailwind.md#variantes-de-contraste-y-movimiento).
- **Los colores forzados siguen siendo del sistema.** `forced-colors: active` es el modo de alto contraste del sistema, y ninguno de los dos atributos lo activa ni lo desactiva. La transparencia reducida tampoco tiene atributo; `data-contrast="more"` sigue volviendo opaco el glass, como lo hace el ajuste de más contraste del sistema.

### Color y contraste

Las mediciones de abajo corresponden a los colores incluidos. En cuanto cambies un token de color, vuelve a medir tus propios pares; [Temas → Cambiar el color de marca](./usage/theming.md#cambiar-el-color-de-marca) muestra qué pares comprobar.

| Característica                   | Comportamiento                                                                                                                                                                                                                                                                                                                                    |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Etiquetas rellenas               | La etiqueta `.solid` de cada intención cumple 4.5:1 (WCAG 1.4.3) como texto normal, en ambos temas, en reposo y bajo el puntero. La más baja es success en reposo, con 5.14:1, e info bajo el puntero en modo oscuro, con 5.08:1.                                                                                                                 |
| Texto de warning                 | `--color-warning-contrast` es casi negro, no el color de la página, porque un ámbar lo bastante oscuro para llevar texto blanco ya no parece ámbar.                                                                                                                                                                                               |
| Rellenos parciales               | El color de texto de contraste solo aparece en rellenos por encima de la mitad de intensidad, así que el relleno limitado de un control de texto conserva el color de texto propio de la intención.                                                                                                                                               |
| Color de intención en oscuro     | En modo oscuro, una etiqueta `.soft` o `.ghost` usa el tono `-300` de su intención, así que conserva su matiz en lugar de volverse blanca.                                                                                                                                                                                                        |
| Texto sobre un padre con relleno | Un componente neutro que no es `.solid`, como un badge en un `.btn.primary` o un botón ghost en una `.card.solid.primary`, imprime en el color de texto de su padre en lugar del de la página, en reposo y con hover, así que conserva el contraste del padre. El borde de un campo y el de un toggle sin marcar también se dibujan en ese color. |
| Impresión                        | Una página se imprime con el tema claro, y los componentes con relleno imprimen su fondo (`print-color-adjust: exact`), así que el texto de contraste nunca cae sobre papel en blanco. Una utilidad `dark:` se sigue aplicando al imprimir; consulta [Temas → Impresión](./usage/theming.md#impresión).                                           |
| Marcas de los toggles            | Una marca activada, y la perilla de un switch encendido o apagado, mide al menos 3:1 frente a cada relleno que su presentación pueda darle, en ambos temas. En un `.switch.solid` apagado, la perilla es el color del texto de la placa.                                                                                                          |
| Rellenos soft con borde          | `.edged` en un `.alert`, `.panel`, `.badge`, `.kbd`, `.code` o `.pre` `.soft` dibuja un borde que mide menos de 3:1 frente al relleno del 12% en algunas intenciones, cuáles depende del tema. Mide el par antes de confiar en ese borde como límite de un control. [Contraste aumentado](#contraste-aumentado) lleva todos ellos a 3:1.          |

### Colores forzados y dirección

| Característica      | Comportamiento                                                                                                                                                                                                                                                                                                                                                                                                          |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Colores forzados    | Con `forced-colors: active`, los bordes, los estados activados, el chevron de un `.select` y el valor de una barra de progreso siguen visibles, dibujados con colores del sistema, bajo cualquier estética. Una estética que dibuja su borde como una sombra interior, como `.pixel`, dibuja en su lugar un borde real. El cristal se vuelve opaco, porque los colores forzados conservan la transparencia de un fondo. |
| Dirección del texto | Con `dir="rtl"`, la barra de las citas, el icono de la alerta, el relleno del progreso, el divisor vertical, la perilla del switch, la alineación de las tablas y el chevron de un select cambian de lado. No hace falta ninguna clase.                                                                                                                                                                                 |
| Escrituras unidas   | Los estilos de texto, la etiqueta y la pista de un campo y el espaciado de etiquetas de una estética no añaden espaciado entre letras en un idioma cuya escritura une sus letras, como el árabe, o las cuelga de una línea superior, como el hindi, así que las uniones, las ligaduras y esa línea se mantienen. Define `lang`; consulta [Contenido y layout](./usage/content-and-layout.md).                           |

Con colores forzados, `.text-control`, `.ipt`, `.textarea`, `.select`, los toggles y tu propia clase que hace `@apply text-control` muestran un contorno de foco `Highlight` de 2px. Dentro de un `.input-group`, el grupo dibuja el anillo del campo, dos píxeles por fuera de su propio borde, y el campo no dibuja ninguno, así que un campo con foco muestra un solo anillo; un checkbox, radio, switch o botón del grupo conserva su propio anillo, y el grupo quita el suyo mientras uno de ellos tiene el foco. El punto de entrada native da el mismo contorno a los inputs de texto, selects, textareas, checkboxes y radios sin clase.

Los checkboxes, radios y switches usan los colores del sistema `Canvas`, `CanvasText`, `Highlight` y `HighlightText`, así que activado y desactivado siguen siendo distinguibles: un toggle activado se rellena con `Highlight` y su marca es `HighlightText`, tanto en las clases como en el punto de entrada native. La forma, el tamaño y el espaciado no cambian.

Un `.checkbox`, `.radio` o `.switch` deshabilitado dibuja su borde y su marca en `GrayText` sobre `Canvas`, con opacidad completa, esté marcado o no, como el sistema dibuja sus propios controles deshabilitados: si se atenuara, uno marcado se leería como un toggle habilitado tenue. Los checkboxes y radios sin clase del punto de entrada native hacen lo mismo.

Una barra `.progress` hace lo mismo: su parte rellena es `CanvasText` sobre un carril `Canvas` con un contorno `CanvasText`, sea cual sea su intención o su presentación, así que una barra a medio llenar no se confunde con una vacía. El brillo de `.active` no se dibuja.

## Lo que hace falta fuera del CSS

Usa el elemento HTML que corresponde a lo que hace el componente, y añade el comportamiento que el CSS no puede dar.

| Interfaz            | Lo que añade tu aplicación                                                                                                                                                                                                                                       |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Botones             | `<button>` para acciones y `<a href>` para navegación. Un nombre accesible, como `aria-label`, en cada `.btn.icon`.                                                                                                                                              |
| Formularios         | Un `<label>` para cada control, el `type` correcto, validación y `aria-describedby` enlazando pistas y errores. Mantén las pistas y los errores fuera del `<label>`, y dale a un `.switch` `role="switch"`.                                                      |
| Alertas             | `role="status"` para una confirmación como "Perfil guardado", o `role="alert"` para un error que necesita atención inmediata.                                                                                                                                    |
| Toasts              | Una región live, una forma de cerrarlo, reglas de foco y una pausa en cualquier temporizador.                                                                                                                                                                    |
| Tooltips            | Un `id` real y `role="tooltip"` en la burbuja, referenciado desde el `aria-describedby` del disparador. El cierre con Escape escribiendo `data-state="closed"`; consulta [Tooltips](./usage/tooltips.md#hover-permanencia-y-escape). La burbuja ya admite hover. |
| Progreso            | Un elemento `<progress>`, o `role="progressbar"` o `role="meter"` con valores ARIA, cuando el valor debe anunciarse.                                                                                                                                             |
| Skeletons           | `aria-hidden="true"` en los elementos visuales de carga, incluido un spinner que aportes tú, y el estado de carga anunciado de otra forma cuando haga falta.                                                                                                     |
| Movimiento continuo | Una forma de pausar, detener u ocultar el movimiento que no es esencial; consulta [Feedback → Animación que no se detiene](./usage/feedback.md#animación-que-no-se-detiene).                                                                                     |
| Popovers, modales   | Atrapar el foco, cerrar con Escape, un fondo inerte, etiquetas y roles.                                                                                                                                                                                          |

## Atributos de estado

Prefiere los atributos nativos:

```html
<button class="btn primary" disabled>Saving…</button> <input class="ipt" type="email" aria-invalid="true" aria-describedby="email-error" />
```

Usa atributos ARIA o data donde el elemento o tu librería de componentes no tenga uno nativo:

```html
<a class="btn secondary" role="link" aria-disabled="true" tabindex="0">Export data</a>
<span class="tooltip" data-state="open">
  <button type="button" class="tooltip-icon" aria-label="About public profiles" aria-describedby="public-profile-help">?</button>
  <span class="tooltip-bubble" role="tooltip" id="public-profile-help">Anyone with the link can see your name and photo.</span>
</span>
```

`aria-disabled="true"` indica a las tecnologías de asistencia que el control está deshabilitado, pero no impide un clic ni una pulsación de tecla. Usa el atributo `disabled`, o detén la acción en JavaScript. A un enlace deshabilitado se le quita el `href`, y un `<a>` sin él no tiene rol ni lugar en el orden de tabulación, así que el ejemplo restaura ambos con `role="link"` y `tabindex="0"`.
