# 0.10.0

Every Tailwind source path now ends in `/tw`, so the source of a compiled entrypoint is its path with `/tw` added; `/palette`, compiled only, has none. Node.js 26 is the floor. The compiled stylesheets are built by the package's own build instead of Tailwind, and ship the same CSS as before.

## Changed

- **Breaking: the focused Tailwind source paths end in `/tw`.** `@codenhub/styles/tw/<name>` is now `@codenhub/styles/<name>/tw`, such as `@codenhub/styles/button/tw` and `@codenhub/styles/native/tw`, and `@codenhub/styles/tw/aesthetics/<name>` is now `@codenhub/styles/aesthetics/<name>/tw`. The old paths are gone, with no alias. Move `/tw` to the end of each import. `@codenhub/styles/tw` is unchanged. See [Tailwind CSS v4 → Using a focused entrypoint](../integrating/tailwind.md#using-a-focused-entrypoint).
- **Breaking: Node.js 26 or newer.** `engines.node` is `>=26`, so Yarn 1, and npm with `engine-strict`, refuse the install on Node.js 24, and `chs build` exits with an error there. Update Node.js where the package is installed or the CSS is built; the stylesheets themselves need nothing. See [Setup → Requirements](../setup.md#requirements). ([#553](https://github.com/codenhub/codenhub/issues/553))
- **The compiled stylesheets are built without Tailwind.** The package compiles them with its own build, and they carry the same rules as in 0.9.0. Through `/tw`, your Tailwind compiles the same classes as before. The only difference is the nine `--tw-*` property registrations the package's classes use, which every `/tw` entry that carries the theme now emits on every page, about 0.7 KB. `NOTICE` now carries Tailwind's MIT licence, for the parts of Tailwind's theme, Preflight, and registrations the package ships.

## Fixed

- **`chs build` reads a `--content` path whose name holds a bracket.** A path that names an existing file, such as Next.js's `app/[id]/page.tsx`, is now read as that file; before, it was read as a glob, in which `[id]` matches one letter, so the build failed with "matches no file". A path that names no file is still read as a glob. A glob that matches a link to a file now reads the file it links to, where it used to skip it. See [Without a bundler → Build only the classes you use](../integrating/without-a-bundler.md#build-only-the-classes-you-use).
- **`chs build` no longer reads its own output.** A `--content` glob that matched the `--output` file, such as `-c "src/**/*" -o src/stylekit.css`, read the previous build back in, so the stylesheet kept every class it had ever held and grew with each build. The output is now left out of the content.
- **`chs build` reads content one file at a time.** It held the text of every file a glob matched at once, so a broad glob over a large folder, such as `node_modules`, could take gigabytes of memory; it now holds one file and the classes found so far. A file that cannot be read because it is too large is now named in the error.
