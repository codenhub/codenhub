# 0.10.0

Every Tailwind source path now ends in `/tw`, so the source of a compiled entrypoint is its path with `/tw` added. Node.js 26 is the floor. The compiled stylesheets are built by the package's own build instead of Tailwind, and ship the same CSS as before.

## Changed

- **Breaking: the focused Tailwind source paths end in `/tw`.** `@codenhub/styles/tw/<name>` is now `@codenhub/styles/<name>/tw`, such as `@codenhub/styles/button/tw` and `@codenhub/styles/native/tw`, and `@codenhub/styles/tw/aesthetics/<name>` is now `@codenhub/styles/aesthetics/<name>/tw`. The old paths are gone, with no alias. Move `/tw` to the end of each import. `@codenhub/styles/tw` is unchanged. See [Tailwind CSS v4 → Using a focused entrypoint](../integrating/tailwind.md#using-a-focused-entrypoint).
- **Breaking: Node.js 26 or newer.** `engines.node` is `>=26`, so Yarn 1, and npm with `engine-strict`, refuse the install on Node.js 24, and `chs build` exits with an error there. Update Node.js where the package is installed or the CSS is built; the stylesheets themselves need nothing. See [Setup → Requirements](../setup.md#requirements). ([#553](https://github.com/codenhub/codenhub/issues/553))
- **The compiled stylesheets are built without Tailwind.** The package compiles them with its own build, and they carry the same rules as in 0.9.0. Through `/tw`, your Tailwind compiles the same classes as before. The only difference is the nine `--tw-*` property registrations the package's classes use, which it now always emits, about 0.7 KB. `NOTICE` now carries Tailwind's MIT licence, for the parts of Tailwind's theme, Preflight, and registrations the package ships.
