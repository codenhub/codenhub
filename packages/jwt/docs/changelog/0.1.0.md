# 0.1.0

0.1.0 is the release `@codenhub/oidc` and the applications built on it are meant to build on. It adds `importKeyPair`, closes what an audit of 0.0.1 found, and raises the Node.js floor to 26. Each breaking change is marked below with what to do.

## Added

- `importKeyPair(privateJwk, { alg, extractable? })`, which loads a signing key stored with `exportPrivateJwk` as `{ privateKey, publicKey }`, like `generateKeyPair`'s result, so the public JWK no longer has to be stored beside it. It proves the two halves belong together by signing and verifying a fixed message, so a JWK whose public members belong to another key is `invalid_key`. [Keys](../keys.md#importing-a-key-pair) covers it.
- An [API reference](../reference/index.md) generated from the package's TSDoc.

## Changed

- **Breaking.** `engines.node` is `>=26`, so Yarn 1, and npm with `engine-strict`, refuse the install on Node.js 24 or 25. Upgrade Node.js to 26. Browsers, Deno, Bun and Cloudflare Workers are unaffected. ([#553](https://github.com/codenhub/codenhub/issues/553))
- **Breaking.** `createVerifier` and `createRemoteKeySet` throw a `TypeError` naming any option they do not know, even one set to `undefined`. In 0.0.1 a typo such as `audiance` was ignored, which turned the audience check off without a sign. Fix the name the error gives.
- **Breaking.** When `now` returns anything but a finite number, the verifier's promise rejects with a `TypeError`, and so does a remote key set's `select`, which a verifier reports as `key_fetch_failed` with `{ reason: "key_set_error" }`. In 0.0.1, `now: () => NaN` passed expired tokens and kept a remote key set's cache from ever expiring. Return milliseconds, as `Date.now` does.
- **Breaking.** `importSecretKey` takes `Uint8Array | object`, so passing a string is a compile error. At run time a string still returns `invalid_key`. Encode the secret to bytes first, such as with `new TextEncoder().encode(secret)` when it is text.
- **Breaking.** `sign` rejects `-0`, which JSON writes as `0`; an array whose prototype is not `Array.prototype`; and a value with a `toJSON` method anywhere on its prototype chain, a polluted `Object.prototype` or `Array.prototype` included. Each would have signed a different value than the one given. Pass plain data.
- **Breaking.** A custom key set's failure is passed through only when every issue is an object with a string `code` of its own; a list with a hole, or an issue without such a `code`, gives `key_fetch_failed` with `{ reason: "key_set_error" }`, as other key set mistakes already did. Return issues built as `{ code: "unknown_kid" }`.
- `typ` compares ASCII letters without regard to case, and drops a leading `application/` only when no other `/` follows, as RFC 7515 §4.1.9 says. 0.0.1 used `toLowerCase`, which also folded some letters beyond ASCII, such as the Kelvin sign (U+212A) to `k`, and dropped `application/` from values such as `application/a/b`. A `typ` spelled that way no longer matches.

## Fixed

- Key options are read as own properties, so a polluted `Object.prototype` can no longer make a generated or imported key extractable.
- `importSecretKey` and JWK import accept a `Uint8Array` or a plain object from another realm, as Jest and jsdom give, which 0.0.1 refused as `invalid_key`.
- A remote key set treats a clock that steps back as an expired cache and an ended cooldown, so a removed key stops being trusted at most `cacheTtl` plus `maxStale` after the last successful fetch, as documented.
