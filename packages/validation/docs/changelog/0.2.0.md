# 0.2.0

0.2.0 settles the API that 0.1.0 introduced. Every validator now takes its arguments in one order, its own, then options, then checks, and every one that reports an issue takes a `message`. The rarer constraints moved from options into checks you import only when you use them, and the helpers that build the built-in validators are public, so your own behave exactly as they do. Some 0.1.0 calls change; the [migration table](#migrating-from-010) maps each one.

## Added

- Checks: rules about a value that already has its type, given to a validator after its options, as in `string({ min: 3 }, startsWith("a"))`. A check runs once the value has its type, for a format once the text is of the format, and for an object once every property has passed, so it can compare fields, and every check's issue is reported. The built-in ones are `pattern`, `startsWith`, `endsWith`, `includes`, `lowercase`, `uppercase`, `multipleOf`, `nonZero` and `unique`.
- `check(test, issue?)`, `format(name, test)` and `guard(expected, typeGuard)`, which build checks, string formats and validators for any type on the same internals as the built-in ones, with the same issue shapes, `message` option and checks. The `Check`, `AsyncCheck` and `Message` types.
- A `message` option on every validator that reports an issue of its own, as text or a function of the issue, and a message argument on every built-in check, so one field can have its own sentence without a message map. The option also words what the validator's checks report without a message of their own, so `string({ message: "Invalid username" }, pattern(/^\w+$/))` never shows a user the pattern.
- Parts of `url` and `email`: `url({ host, port, path, query, repeated })` and `email({ domain, local })` take validators that check what the parser read. `domain()` and `port()` validate those parts on their own, and `searchParams(validator)` reads a query string, or a `URLSearchParams` from any realm, into typed values. A repeated query key fails unless `repeated` is set. A part that fails is one `invalid_format` issue at the place of the URL or address, with `params` `{ format, part, issues }`, so a form shows it beside the field, and the format's `message` words it. With a `path` validator, a path holding an encoded `/` or `\` (`%2F` or `%5C`) fails before the validator runs, with `{ encodedSeparator: true }` inside the path part's issue, so `/api/..%2fadmin` cannot pass a check for `/api/` and reach `/admin` on a server that decodes the separator before routing.
- Formats: `phone` (E.164), `slug`, `semver`, `jwt` (its structure), `creditCard` (the Luhn checksum), `cidr`, `mac`, `time` and `duration`, with `base64({ url: true })` for base64url, `uuid({ version })` for one version, and `datetime({ local: true })` for a date-time without a zone, such as an HTML `datetime-local` value.
- `symbol()`, and `oneOf` over a TypeScript `enum`.
- `optional(validator, value)`, which replaces a missing value with a default.
- `tuple(items, { rest, max })`: `max` caps the length of a tuple with `rest`, the fixed items included, so untrusted input can be bounded as an `array` is.
- English wording for every new format and check in `englishMessages`.

## Changed

- **Breaking.** `string`'s `pattern`, `startsWith`, `endsWith` and `includes` options are checks of the same names, and `number`'s `multipleOf` and `nonZero` are checks too. Their issues are unchanged, except that `multipleOf` reports `{ type: "number", format: "multipleOf", value }`, as the other number rules name themselves in `format`, where 0.1.0 reported `{ type: "number", multipleOf }`.
- **Breaking.** `string`'s `lowercase: true` and `uppercase: true` options are `case: "lower"` and `case: "upper"`. The `lowercase()` and `uppercase()` checks now require a case without changing the string.
- **Breaking.** `array`'s `unique` option is the `unique(by?)` check, and its callback is its first argument.
- **Breaking.** `url`'s `allowLocal` option is gone. A host validator replaces the rule that the host is a public domain: `url({ host: hostname() })` accepts any hostname, and `url({ host: unknown() })` any host the parser reads, as `allowLocal: true` did. A `mailto` recipient must now have a public domain whatever the options, where `allowLocal` accepted any hostname.
- **Breaking.** `ip()` produces an IPv6 address in its canonical form, lowercase with the longest run of zero groups shortened, so `0:0:0:0:0:0:0:1` is `::1`. An IPv4 address is produced as written, as before.
- **Breaking.** `invalid_type` names kinds of value and never a class: a class instance, a `Map` and a `Set` are `object`, where 0.1.0 named the class, `map` or `set`. A `Date` from another realm is `object` too.
- **Breaking.** `array` and `set` report a child that is not a function as `item`, where 0.1.0 named it `element`.
- **Breaking.** `isoDate()` reports `invalid_format` with `{ format: "isoDate" }`, the name of its validator as every other format reports, where 0.1.0 reported `"date"`.
- **Breaking.** `hostname()` and `uuid()` produce lowercase and `ulid()` uppercase, the canonical spelling of each, so one value is one string however it was written, where 0.1.0 produced them as written.
- **Breaking.** An option of the wrong type throws a `TypeError` when the validator is made, where 0.1.0 ignored it or read it as another value: a bound of `number` that is not a number or of `bigint` that is not a bigint, a `clamp` without a number `min` and `max`, a flag such as `int`, `trim`, `offset`, `url`, `repeated` or `allowPlus` that is not a boolean, a part validator of `url` or `email` that is not a function, `protocols` that is not a non-empty list, `unique(by)` with a `by` that is not a function, a `message` that is neither text nor a function, such as a group of translations that would reach a form as `[object Object]`, `oneOf` given text, which it read as a list of characters, an object or a function given to `literal` or `oneOf`, which equals only itself, text that is not text given to `startsWith`, `endsWith` or `includes`, such as a variable that is not set, which they required as `"undefined"`, a name that is not text given to `format` or `guard`, and an issue given to `check` that is neither text nor an issue, or whose `path` is not a list. The types already forbade each.
- **Breaking.** A size limit, `datetime`'s `precision`, `lazy`'s `maxDepth`, `multipleOf`'s step or a `date` bound that is not of its type at all, such as `string({ min: "3" })` or `date({ min: "2026-01-01" })`, throws a `TypeError`, where 0.1.0 threw a `RangeError`. A value of the right type that makes no sense, such as a negative size or an invalid `Date`, still throws a `RangeError`.
- **Breaking.** `lazy` limits the calls one outermost `lazy` call makes, 100,000 by default and set with `maxCalls`, and fails past it with `too_big` and `{ maximum, type: "calls" }`. A recursive `union` of objects does its work again for every option at every level, so a valid input of a few hundred bytes could run for hours; 0.1.0 had no such limit. Recursive data with more nodes than that under one root needs `maxCalls` raised. Each outermost `lazy` call has its own count, and only its `maxCalls` is read, so wrap the root of a schema for untrusted input in `lazy(() => schema, { maxCalls })` to hold the whole validation to one, and set the limit there.
- **Breaking.** `email()` and `url()` reject a domain whose top-level label is longer than 63 characters, which no domain name can have, where 0.1.0 accepted it, as `hostname()` already rejected it.
- **Breaking.** `url()` produces the host of a listed scheme the URL parser has no rules for, such as `ssh` or `postgres`, in lowercase with its escapes in uppercase, and gives it so to a `host` validator, where 0.1.0 produced it as written, so two spellings of one URL were two values.
- **Breaking.** `tagged` throws a `TypeError` when its key is not text, its variants are not a plain object or it has no variant, `standard` when its message map is not an object, `union` when its options and `tuple` when its items are not a list, and `tuple` when it has no item, where 0.1.0 named the property `"undefined"`, took a list's indexes for tags, rejected every value, worded every issue "Invalid value", threw that the value is not iterable, or made a `tuple` that accepts only the empty list. The types already forbade each.
- `intersection` merges `0` and `-0` as `0`, where 0.1.0 reported them as `invalid_intersection`.
- **Breaking.** `multipleOf` reads a whole number beyond `Number.MAX_SAFE_INTEGER` as it is written, as it reads a fraction, where 0.1.0 compared the double it is held as. So `1e23` is a multiple of `10`, which 0.1.0 rejected, since the double is `99999999999999991611392`, and `2 ** 60`, written `1152921504606847000`, is not one of `1024`, which 0.1.0 accepted.
- **Breaking.** `base64()` rejects the empty string, as `hex()` does, where 0.1.0 accepted it as the encoding of no bytes.
- **Breaking.** A factory throws a `TypeError` when its first argument is neither options nor a check, such as `string("abc")`, which 0.1.0 read as options, or `array(item, [unique()])`, whose checks in a list would be dropped, and when its options are an object that is not a plain one, such as `string(/^a/)` where `string(pattern(/^a/))` was meant, which 0.1.0 read as options and ignored, accepting every string. `object` and `partial` throw one for a shape that is a list. The types already forbade each.
- `standard(validator)` returns a `Promise` from `~standard.validate` for any asynchronous validator, where a validator of your own that returned another kind of thenable had it returned as it was, which a caller testing for `instanceof Promise` read as a result without issues.
- `coerceDate` reads a time without seconds, `2026-09-28T14:30`, as an HTML `datetime-local` input sends it.
- `array`, `tuple`, `instanceOf` and `searchParams` reject an input that throws when inspected, such as a revoked `Proxy`, as the wrong type instead of throwing, as the other validators already did, and `instanceOf` throws when it is made for a function `instanceof` cannot test against, such as an arrow function.
- **Breaking.** A `mailto` URL fails when its `subject` holds an encoded line break (`%0D` or `%0A`), which RFC 6068 expects in `body` alone and which would let a mail program that writes the subject unescaped read a header such as `Bcc:` after it, and when `subject` or `body` appears more than once, which leaves the one a mail client uses to the client. 0.1.0 accepted both. `to`, `cc` and `bcc` may still repeat.
- **Breaking.** `email()` and `url()` treat every name under `.arpa`, such as `1.0.0.127.in-addr.arpa`, and the eleven IDN test top-level domains IANA reserved, such as `.テスト` (`xn--zckzah`), as special-use names, which are not public hosts, where 0.1.0 rejected only `home.arpa` among them. `domain()` applies the same rule.
- `url()` accepts an absolute host, `https://example.com./`, and keeps its final dot in the value, as the parser does, where 0.1.0 rejected it; `domain()` accepts `example.com.` the same way. The dot is not counted toward the 253-character limit. `email()` still rejects a domain ending in a dot.
- `object` with an asynchronous property builds its output from the input as it was when called, where 0.1.0 read the keys `passthrough` copies, and whether a property is present, again once the property had settled, so a change made to the input meanwhile reached the output unchecked.

## Removed

- **Breaking.** `refine`: a check given to the validator does the same and reports its issue with the others. `refine` checks written as type guards narrowed the output type, which a check does not.
- **Breaking.** `withDefault`: use `optional(validator, value)`.
- **Breaking.** `nativeEnum`: use `oneOf(Enum)`.
- **Breaking.** `discriminatedUnion` is renamed `tagged`, with the same behavior, and its type `InferDiscriminated` is `InferTagged`.

## Migrating from 0.1.0

Everything not listed carries over unchanged.

| 0.1.0                                                       | 0.2.0                                                                           |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `string({ pattern: re })`                                   | `string(pattern(re))`                                                           |
| `string({ min: 3, startsWith: "a" })`                       | `string({ min: 3 }, startsWith("a"))`                                           |
| `string({ endsWith: s })`, `string({ includes: s })`        | `string(endsWith(s))`, `string(includes(s))`                                    |
| `string({ lowercase: true })`                               | `string({ case: "lower" })`                                                     |
| `string({ uppercase: true })`                               | `string({ case: "upper" })`                                                     |
| `number({ multipleOf: 5 })`                                 | `number(multipleOf(5))`                                                         |
| `number({ int: true, nonZero: true })`                      | `number({ int: true }, nonZero())`                                              |
| `array(item, { max: 5, unique: true })`                     | `array(item, { max: 5 }, unique())`                                             |
| `array(item, { unique: (user) => user.id })`                | `array(item, unique((user) => user.id))`                                        |
| `refine(validator, test, issue)`                            | `validator(check(test, issue))`, such as `string(check(test, issue))`           |
| `refine(object(shape), test, issue)`                        | `object(shape, check(test, issue))`                                             |
| `refine(object(shape, options), test, issue)`               | `object(shape, options, check(test, issue))`                                    |
| `withDefault(validator, value)`                             | `optional(validator, value)`                                                    |
| `nativeEnum(Enum)`                                          | `oneOf(Enum)`                                                                   |
| `discriminatedUnion(key, variants)`                         | `tagged(key, variants)`                                                         |
| `url({ allowLocal: true })`                                 | `url({ host: hostname() })`, or `url({ host: unknown() })` for IP addresses too |
| `refine(unknown(), (value) => typeof value === "function")` | `func()`                                                                        |

A `refine` that wrapped a validator which had no place for checks, such as `refine(optional(string()), test)`, moves the check onto the inner validator: `optional(string(check(test)))`. A check runs only on a value of its type, so it never sees the `undefined` that `optional` lets through.
