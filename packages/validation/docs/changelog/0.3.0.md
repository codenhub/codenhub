# 0.3.0

0.3.0 makes the package a regular dependency and adds what its first adopter had written around it: a helper that throws for invalid configuration, wording for a few codes without the whole English map, and a validator for objects that are not plain. It also bounds what a failing input costs. Every signature of 0.2.0 is unchanged.

## Added

- `assert(validator, input, { subject, messages })`, which returns the value a validator produces or throws a `TypeError` naming the first issue and its path, as in `[I18n] locales[1]: Expected string, received number`, with the failure as the error's `cause`. It is for input whose being invalid is a caller's mistake, such as an options object; a form or a request is still read from the result. Its `messages` are optional, and it takes a synchronous validator only.
- `objectLike(shape, options?, ...checks)`, for any object that is not an array, such as an `Error` or another class instance, which `object` rejects. Each listed property is read as `input[key]`, so an inherited one, a non-enumerable one or a getter counts, and a property that throws while it is read is an `invalid_value` issue with `params.unreadable`, not an exception. The output is a new plain object of the listed properties.
- The English wording of each code as an export of its own: `invalidTypeMessage`, `tooSmallMessage`, `tooBigMessage`, `invalidFormatMessage`, `invalidValueMessage`, `invalidKeyMessage`, `unrecognizedKeyMessage`, `invalidIntersectionMessage` and `invalidUnionMessage`. A program that can report three codes passes a map of those three and bundles no other wording. `englishMessages` is the map of all of them, as before.
- `nonBlank()`, a check that requires a string to hold a character that is not white space and leaves the string as it is, where `string({ trim: true, min: 1 })` trims it.

## Changed

- **Breaking.** A collection stops once its items have reported 1,000 issues. `array`, `tuple`, `set`, `map` and `record` validate no further item, cut their list there and add one `too_big` issue with `params` `{ maximum: 1000, type: "issues" }` at their own place, worded "Stopped after 1000 problems, so there may be more". An issue counts with the issues it holds in `params.issues`, as a `union`'s holds its options'. The unknown keys of a strict `object`, the repeats `unique` and `set` report, the keys a query string repeats and the conflicts of an `intersection` are cut the same way. Input that fails still fails and input that passes is unaffected; a program that must list every bad row of a long list validates the rows one at a time. A megabyte of bad items under a `union` took 5.9 s and 1 GB to report, and takes 71 ms and 25 MB.
- **Breaking.** An option that 0.1.0 had and 0.2.0 removed, such as `string({ pattern })`, throws `TypeError: Unknown option pattern`, as any name a factory does not read does, where 0.2.0 threw an error naming the replacement. The [0.2.0 changelog](0.2.0.md#migrating-from-010) still maps each one.
- **Breaking.** An entry of a message map must be text or a function that returns text. `formatIssue`, `flatten`, `assert` and `standard` throw a `TypeError` for anything else, such as a translation lookup that returned `undefined`, where 0.2.0 returned it and a form showed `undefined` or `[object Object]`.
- A primitive that ends a recursion no longer counts toward `lazy`'s `maxCalls`. A schema for any JSON value, whose arrays hold `lazy` items, rejected a valid list of 10,001 numbers in 0.2.0, and now accepts it. Objects and arrays count as before, and so does a primitive the recursion goes on through, such as text a `json` reads the next level from, or one whose result is pending, as under an asynchronous `check`.
- `englishMessages` words a `union` that a limit of `lazy` stopped with the limit, "Too complex to check within 10000 recursive steps", whatever its other options found, where 0.2.0 said "Does not match any of the allowed types" unless exactly one option was the one meant.
- The package is meant to be a regular `dependency` of a package that validates with it, where 0.2.0 recommended inlining it. A fix then reaches every adopter with one update, and an application carries the shared core once.

## Fixed

- `email`, `url` and `domain` no longer take time that grows with the square of a host's length. The runtime's URL parser decodes a punycode label that way, so `email()` took 0.3 s to reject `a@xn--` and 100,000 letters and 5 s for 400,000, in Node.js 24.19, however `url` was given the `xn--`: in capitals, in fullwidth letters or as an escape. A host written with more than 759 characters, three for each one a host can have, is now rejected before the parser reads it. A host that long was valid only when padded with characters the parser drops.
- `lazy` no longer slows with the square of the places one object is reached at. With `maxCalls` raised, 80,000 rows that shared ten objects took 7.8 s to validate, and take 0.2 s.
- A recursive `union` with many options no longer overflows the stack inside `lazy`'s default `maxDepth`. With twenty options before the recursive one, 3 kB of valid input nested 120 levels threw `RangeError: Maximum call stack size exceeded` in a fresh Node.js process and in Chromium, since every option that failed stayed on the stack while the next ran.
- `object` reads each validator of its shape once, when it is created. It read the property to check it and again to keep it, so a shape whose property is a getter could be checked as one value and run as another.
