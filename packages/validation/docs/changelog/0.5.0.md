# 0.5.0

0.5.0 adds no export. It makes what the package already did hold where it did not: the JSON Schema it writes compiles in Ajv and accepts what the validator accepts, `encode` writes a codec back through its output, `audit` finds bounds it missed, and recursion that waits between levels stops at `maxDepth`. Nine changes are breaking, each marked below with what to do. Six change what `toJsonSchema` writes or when it throws, and how `pick` and its kin, `encode` and asynchronous recursion behave. The other three refuse input 0.4.1 accepted, or throw where it returned: a `__proto__` key an `intersection` copied, text of invisible characters in `nonBlank`, and a validator written by hand that returns a failure with no issues. The README and the guides are now also written in Brazilian Portuguese and Spanish.

## Added

- The README and every guide are available in Brazilian Portuguese and Spanish, as `README.pt-BR.md` and `README.es.md` and under `docs/pt-BR/` and `docs/es/`. The English pages stay the source, and the API reference and this changelog are in English only.

## Changed

- **Breaking.** `pick`, `omit`, `partial`, `required` and `extend` merge the options they are given into those of the object they come from, where 0.4.1 replaced all of them when given any. So `pick(strictUser, ["name"], { message: "Invalid user" })` stays strict, where it quietly turned to stripping unknown keys. An option given as `undefined` counts as not given, so `{ unknownKeys: config.mode }` with no mode set keeps the original's. A name the object does not know still throws, as `object` does, even given as `undefined`: `{ unknownkeys: config.mode }` is a `TypeError`. To get the old result, name the option you want: `pick(strictUser, ["name"], { unknownKeys: "strip", message: "Invalid user" })`. [Shaping values](../shaping-values.md#pick-omit-required-partial-and-extend) covers it.
- **Breaking.** `encode` writes a codec's value back through its `output` first, then gives the result to the codec's `encode` function, where 0.4.1 checked the value with `output` read forward. So a codec inside the output writes its part first: for `codec(string(), object({ at: expiresAt }), …)`, where `expiresAt` is a codec of text to a `Date`, the outer `encode` is given `{ at: "2026-10-07T12:00:00.000Z" }` where it was given the `Date`. `Conversions["encode"]` is typed to receive `InferInput<typeof output>`, so an `encode` function typed for the decoded value fails to type check: type its argument as the output's input type. A `transform` in a codec's output now throws the `TypeError` that names its place, where 0.4.1 ran it forward: `codec(string(), transform(number(), (n) => n * 2), …)` encoded `42` as `"84"`, which decodes to `168`. Use a codec there. An output written by hand still only checks the value. [Shaping values](../shaping-values.md#encode) covers it.
- **Breaking.** A recursive schema that waits at each level, such as one with an asynchronous `check` on every node, is held to `maxDepth`, 128 by default, as a synchronous one is. 0.4.1 counted levels only until the first `await`, so such a schema had no limit but `maxCalls`, and a body of 10,000 nested levels, each with a field that fails, under 200 kB, kept 402 MB in memory. Valid data nested deeper now fails with `too_big` and `{ type: "depth" }`. If yours is that deep, raise `maxDepth` on the `lazy`, as [Limits](../limits.md#maxdepth) explains.
- **Breaking.** `toJsonSchema` writes a `format` only where JSON Schema names it and its rules accept what the validator accepts. So `new Ajv()` with ajv-formats compiles every schema it writes, which it refused for one holding a format such as `phone` or `slug`, and a reader accepts what the validator accepts, which it did not for `user@bücher.de` under `email()`. It writes none for the input of `email` and `domain`, which may be internationalized, for `time`, `duration`, `url`, an `ip` other than `version: "v4"` and a `datetime` with `local`, for the formats JSON Schema has no name for, such as `phone`, `slug`, `ulid` or `creditCard`, and for any format made with `format`, even one named `"uuid"`. The output of `email` and `domain` keeps `email` and `hostname`. A reader that registered a name such as `phone` no longer checks it from the schema; add the keyword to the schema you hand it. [JSON Schema](../json-schema.md#how-each-validator-is-written) lists what each format is written as.
- **Breaking.** `toJsonSchema` writes the input of a coercion as an `anyOf` of the type it produces, with its bounds, and the types it converts from: `coerceNumber({ min: 5, max: 10 })` is `{ anyOf: [{ type: "number", minimum: 5, maximum: 10 }, { type: "string" }] }`, where it was `{ type: ["number", "string"] }`. A reader now refuses `20` there, as the validator does. Code that reads the `type` of such a schema reads the `anyOf`.
- **Breaking.** `toJsonSchema`, and the `libraryOptions` of `standardJsonSchema`, throw a `TypeError` for an option they do not know, such as `{ draft: "draft-07" }` where `target` was meant, which 0.4.1 ignored; `null` counts as no options. They also refuse a `pattern` with the `v` flag, and one written without `u` that Unicode mode reads otherwise, such as `/^\p{L}$/`, which without `u` matches the text `p{L}`, since a schema reads every pattern in Unicode mode. Remove the unknown option; write such a pattern with `u`, or pass `unrepresentable: "any"` to leave it out. [What cannot be written](../json-schema.md#what-cannot-be-written) lists each case.
- **Breaking.** `intersection` reports an own `__proto__` key that one side passed on unchecked, as `unknown()` does, as `invalid_key` with `{ reserved: true }` inside, as `record` does since 0.4.0. 0.4.1 copied it into the object it built, so `Object.assign({}, output)` of the validated `{"__proto__":{"admin":true}}` had `admin`. A shape of either side that lists `__proto__` at that place keeps it, when that shape made the value there: one before a `transform`, or in a step of a `pipe` before a step that makes a new object, does not, and neither does the key of a `map` entry for its value. A value both sides pass on whole is kept unchanged. [Request bodies](../request-bodies.md#intersection) covers it.
- **Breaking.** `nonBlank()` counts invisible characters as blank: the format characters such as the zero-width space U+200B and the soft hyphen, the Hangul fillers and the blank braille pattern U+2800. Text of only those looks empty and now fails, where 0.4.1 required only a character that is not white space. Data that passed before may fail when validated again.
- **Breaking.** A validator written by hand that returns a failure with no issues, `{ ok: false, error: { issues: [] } }`, is now no result, and every composer throws the `TypeError` naming where it is, where `object`, `tuple` and `array` passed, leaving out the value it refused. A passing result is still read by its `ok` alone, so its `error` is never read. `is()` reads a result as `assert` does, so it throws for that failure, and for a validator that returns no result, where it returned `false`. `fallback` throws for a validator that returns no result, such as `string` given uncalled, where it returned the fallback value for every input, and the key validators of `record` and `map` throw the same `TypeError`, where they threw one from reading `undefined`. Return at least one issue from a failure, for example with `fail`. [Custom validators](../custom-validators.md#a-validator-that-returns-no-result) covers it.
- The short English of a validator's own `~standard`, which a form library shows, words a check and a format whose name is camelCase as "Invalid value", where it said "Invalid startsWith" or "Invalid creditCard", and so a format named with a digit before a capital, such as `sha256Hash`; a one-word format keeps "Invalid email". It says "Unrecognized key" without the key, which the path holds, writes a date bound in UTC, so the text is the same on every machine, and words a step as "Must be a multiple of 5". `standard(validator)` still gives the full English.
- `portugueseMessages` writes a bound or a step with a decimal comma, "Deve ser no mínimo 0,1", ends a long list with "e mais 2" where it said "ou mais 2", and words every message about a key in the feminine, "Deve ser informada apenas uma vez".
- Every validator carries the wording above and the stricter reading of a result, so a lone `boolean()` is 2.01 kB gzipped, from 1.86 kB in 0.4.1. `size.json` in the package records each export imported alone.
- The guides were reorganized into pages along one reading path, which [the overview](../index.md#reading-path) lists, and `validators.md` and `coercion.md` were replaced. What they held is now in [Getting started](../getting-started.md) (strings, numbers, other primitives, objects, checks, `Infer` and `is`), [Formats](../formats.md), [Request bodies](../request-bodies.md) (collections, `union`, `tagged`, `intersection`, `lazy`, `json`), [Forms](../forms.md) (optional fields, defaults, files, `InferInput`), [Shaping values](../shaping-values.md) (`pipe`, `transform`, `codec`, `encode`, `brand`, `readonly`, `meta`, `fallback`, `pick` and its kin), [Text input](../text-input.md) (the coercing validators, `searchParams` and the environment), [Limits](../limits.md) (the limits of `lazy` and `audit`), [Issues and messages](../errors.md) (`formatIssue`, `flatten`, `assert` and the wording of one validator), [Custom validators](../custom-validators.md) (`pass`, `fail` and the exported types), [Standard Schema](../standard-schema.md) (handing a validator to other libraries) and [JSON Schema](../json-schema.md#reading-a-schema) (`describe`). The README keeps one example, and `llms.txt` links every page with a line on what it covers.

## Fixed

- `coerceBigint` refuses text with more digits than its bounds allow before converting it, with the issue of the bound it passes, since converting takes longer than linear time: 8,000,000 digits took 0.8 seconds in one measurement, and are refused in 4 ms.
- `date()` and `coerceDate()` no longer ask a plain object whether it is a `Date` by catching a throw: in one measurement, 100,000 `{}` under a `union` with `date()` took 2 seconds, and take 40 ms.
- A value quoted in a message, such as an unrecognized key, escapes U+2028, U+2029 and the C1 controls, so text the sender chose cannot start a new line in a log.
- `domain()` and `email()` accept a zero-width non-joiner or joiner where IDNA allows one, as in `می‌خواهم.com` or `ශ්‍රී.lk`, which `url()` and the browsers accept. One between Latin letters, such as U+200C in `a‌b.com`, and its punycode `xn--ab-j1t.com`, are still refused.
- `domain()`, `email()`, `url()` and the punycode labels of `hostname()` refuse a right-to-left name holding a character the bidi rule of RFC 5893 does not allow there, such as `¡` or `°` at the end of a label, which 0.4.1 guessed from its Unicode block.
- `url()` given a `host` validator refuses a host written with a Hangul filler, U+115F, U+1160, U+3164 or U+FFA0, as it is or percent-encoded. Node.js, Chromium and Firefox drop the filler and WebKit refuses the host, so 0.4.1 accepted `https://𞤀ㅤ/` as `https://xn--9d6h/`, a URL runtimes read differently.
- A `union` whose options reach the same object through a different number of `lazy` levels no longer gives one option the `maxDepth` failure another met deeper: with `node` a `lazy` of `maxDepth: 2`, `union([lazy(() => lazy(() => node)), node])` refused an object `node` accepts.
- `audit` reports what it missed: a `coerceBigint` without a bound on each side, as `unbounded_text`; the items after a collection's `max` in a `pipe`, which that `max` bounds only in count, unless the items before it are of a fixed size, such as numbers, booleans, dates and literals; and a format made with `format` under a built-in name, such as `format("email", test)`, which bounds no text. It throws a `TypeError` for a recursive schema built anew at every level, where it overflowed the stack. A test that asserts `audit` finds nothing may now fail; give the part the bound it names. [Limits](../limits.md#checking-a-schema-for-the-bounds-it-needs) covers it.
- `toJsonSchema` writes `multipleOf` only for a step binary floating point holds as written, an integer such as `5` or a fraction such as `0.25`, since a reader refused `0.3` against `multipleOf: 0.1`, and `3e23` against `multipleOf: 1e23`, which binary holds as 99999999999999991611392. It writes `uniqueItems` only over primitive items, since `unique()` compares an object by identity. It writes a hyphen in a pattern without `\`, which Unicode mode refuses; writes a `tagged` variant it cannot write, with `unrepresentable: "any"`, as an object holding its tag, so the other variants still match one branch; and writes a long chain of distinct `lazy` parts built once, which it refused past 64 as a schema built anew. [JSON Schema](../json-schema.md#how-each-validator-is-written) also says where Ajv refuses a large multiple.
- `encode` throws a `TypeError` naming the place of a `bigint` inside `json`, which JSON cannot hold.
