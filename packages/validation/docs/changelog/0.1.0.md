# 0.1.0

0.0.1 validated a value the moment you called `val.string(value).min(3)`. 0.1.0 builds a schema first and runs it later: `val.string().min(3).validate(value)`. That one change makes schemas reusable, composable and inferable as types, and it touches every call, so nothing from 0.0.1 carries over unchanged. The tables below map old calls to new ones.

## Added

- Schemas built from `val`: strings, numbers, bigints, booleans, dates, literals, enums, objects, arrays, tuples, records, sets, maps, unions, discriminated unions, intersections, recursive schemas, instances and JSON strings, all inferring their TypeScript type with `Infer`.
- `validate`, `parse`, `is`, `validateAsync` and `parseAsync` on every schema, returning a result or throwing a `ValidationError` that carries every issue.
- `refine`, `check`, `transform`, `pipe`, `and`, `or` and `val.custom` for rules of your own. `refine` and `check` keep the validator's concrete type, so `val.object(...).refine(...).extend(...)` works; `transform`, `pipe`, `and` and `or` wrap it in a general validator, so add type-specific rules first. Any callback may be async.
- Structured issues: an open set of `code`s, `path`, and `params` with the facts behind each failure. Every rule takes a message that can be a function of those facts, which is how messages are localized.
- `ValidationOptions.context`, reaching checks and transforms as `ctx.options.context`, and `abortEarly`.
- Standard Schema v1 support on every schema.
- `val.coerce.string()`, `number()`, `boolean()`, `bigint()` and `date()` for text input, chaining every rule of the plain validator.
- String formats `uuid`, `ulid`, `nanoid`, `cuid2`, `ip`, `hostname`, `datetime`, `date`, `base64`, `hex`, and string rules `startsWith`, `endsWith`, `includes`, `regex`, `trim`, `toLowerCase` and `toUpperCase`.
- Number rules `min`, `max`, `gt`, `lt`, `multipleOf` and `clamp`, and `val.bigint()`.
- Object shape helpers `extend`, `pick`, `omit`, `partial`, `required` and `keyof`, and unknown-key modes `strict`, `passthrough` and `strip`.

## Changed

- **Breaking.** Validators are built first and run with `.validate(input)`. `val.string(value, options)` is now `val.string()`, and its checks are chained before validating:

  | 0.0.1                                        | 0.1.0                                                                |
  | -------------------------------------------- | -------------------------------------------------------------------- |
  | `val.string(x).email()`                      | `val.string().email().validate(x)`                                   |
  | `val.string(x).minLength(3, { trim: true })` | `val.string().trim().min(3).validate(x)`                             |
  | `val.string(x).notEmpty()`                   | `val.string().trim().nonEmpty().validate(x)`                         |
  | `val.string(x).matches(re, message)`         | `val.string().regex(re, message).validate(x)`                        |
  | `val.string(x).url({ forceHttps: true })`    | `val.string().url({ protocols: ["https"] }).validate(x)`             |
  | `val.number(x).range({ min: 1, max: 9 })`    | `val.number().min(1).max(9).validate(x)`                             |
  | `val.number(x).port()`                       | `val.number().int().min(1).max(65535).validate(x)`                   |
  | `val.array<T>(x).minLength(1)`               | `val.array(itemSchema).min(1).validate(x)`                           |
  | `val.object(x).plain()`                      | `val.record(val.string(), val.unknown()).validate(x)`                |
  | `custom(x, fn)`                              | `val.custom<T>(predicate).validate(x)`, or `refine` / `transform`    |
  | `coerce.int(x)`                              | `val.coerce.number().int().validate(x)`                              |
  | `coerce.number(x)`, `coerce.string(x)`       | `val.coerce.number().validate(x)`, `val.coerce.string().validate(x)` |
  | `coerce.bool(x)`                             | `val.coerce.boolean().validate(x)`                                   |

- **Breaking.** `ValidationError` is a class, not an interface, and always carries `issues`, a list of every issue, including for a single failure. Read `code` and `path` from the issues.
- **Breaking.** Issues carry `params` for the facts behind a failure instead of `expected` and `received` strings. Messages name types (`Expected number, received string`) and never echo the input, and `input` appears on an issue only with `includeInput: true`.
- **Breaking.** Validation is a single pipeline that stays synchronous until a callback returns a promise. `validate`, `parse` and `is` throw an `Error` when they reach async work; use `validateAsync` and `parseAsync`.
- **Breaking.** Rules never rewrite the value. `email()` does not lowercase the domain, and `url()` does not normalize. Use `trim()`, `toLowerCase()` and `transform()` for changes you want.
- **Breaking.** `url()` requires a scheme, accepts `http` and `https` unless `protocols` says otherwise, rejects embedded credentials and non-public hosts by default, and accepts `localhost`, single-label hosts and IP addresses with `allowLocal: true`. `email()` and `url()` take their `message` inside their options object.
- **Breaking.** Invalid size limits, such as `min(-1)`, throw a `RangeError` when the schema is built instead of failing every validation.
- **Breaking.** `coerce.number` and `coerce.int` are `val.coerce.number()`, which rejects booleans, empty strings, `"0x10"` and exponents, and chains every number rule. Coercion failures are `invalid_type` and do not repeat the input.
- **Breaking.** Exceptions thrown by your own callbacks propagate instead of becoming validation failures.
- The `path` option is gone. Objects, arrays and the other structural validators produce paths themselves.

## Removed

- The immediate-evaluation calls `val.string(value)`, `val.number(value)`, `val.object(value)`, `val.array(value)`, `custom(value, fn)` and the standalone `coerce.int`, `coerce.number`, `coerce.bool` and `coerce.string` functions. See the table above.
- `ok`, `err`, `parseResult` and the `ValidationErrorInput` and `ValidationErrorOptions` types. Results are produced by validators only; failures you report yourself go through `ctx.addIssue`.
- `fileType()`, `object().hasKeys()`, and the `ArrayValidators`, `NumberValidators`, `ObjectValidators` and `StringValidators` result-builder interfaces.
- `range({ min, max })` and `port()`; chain `min`, `max` and `int` instead. `finite()` is gone because `val.number()` always rejects `NaN` and the infinities.
- `minLength`, `maxLength` and `notEmpty` on strings and arrays; use `min`, `max` and `nonEmpty`. `matches` is `regex`.
