# 0.3.0

## Added

- Documentation in Brazilian Portuguese and Spanish: the README and every public page except the changelog.
- `babysit-pr` answers requests made in review summaries and conversation comments with one pull request comment per round.
- `test-driven-development` covers refactors meant to keep behavior: confirm tests cover it, adding passing characterization tests where they do not, then refactor.

## Changed

- **Breaking.** The package exports no JavaScript API. `parseFrontmatter`, `getSkills`, and `copyRecursiveSync` are gone from the public surface, and `main`, `module`, and `types` with them; only `@codenhub/skills/package.json` resolves. They could not reach the bundled skills, so the installer is the supported way to get them. Copy a skill directory from the package's `skills/` folder if you need it outside the installer.
- The docs are rewritten around choosing skills and installing them, with a catalog that says when an agent uses each skill.
- `babysit-pr` starts when asked to monitor a pull request or handle its CI and reviews, or after opening one as part of a task the user asked to see through, not after every push. Its report lists only failing, rerun, or unfixable checks, names each declined comment once, and holds decision questions for the report unless they block all progress. A bot nitpick fixed as suggested gets a one-line reply.
- `brainstorming` no longer gates bug fixes whose expected behavior is already clear, and its final step summarizes only what changed since the sections were approved.
- `caveman` turns off whenever the user asks for normal style, writes code, comments, commits, pull requests, and files in normal style, keeps real uncertainty, and uses the lite level when the user only asks for shorter answers.
- `caveman-commit` commits, stages, or amends when the user asks for that, follows the project's commit convention when `git log` shows one other than Conventional Commits, and keeps co-author trailers the workflow requires.
- `ponytail` builds everything a complex request asks for, the simplest way, and questions only the extras it skipped.
- `test-driven-development` ships a fix without a test only with the user's approval, and says so in the report. It captures a verification baseline before coding.
- `design` no longer loads for motion graphics. `logo-design` loads for app icons and favicons, not interface icons. `audit` leaves over-engineering reviews out of scope. `project-template` audits only template-based projects.
- `motion-graphics` sets minimum text sizes against the frame's shorter side, with larger minimums for vertical video on phones, holds the end only on a call to action or logo, and always seeds randomness.
- `project-template` reads the template as an `owner/repo` and fetches its default branch instead of `main`, and states that it needs `git`, `pnpm`, and an authenticated `gh`.

## Fixed

- `branding` applied 3:1 contrast to small labels and button text; text below 24px, or 18.66px bold, now needs 4.5:1.
- `project-template`'s local start removed the clone's history before recording the template commit, and its placeholder check missed placeholders outside a fixed list.
- `babysit-pr` could never finish on a pull request whose AI reviewer comments after every push.
- `branding` and `logo-design` told agents to resolve the font and output paths inside the installed skill folder.
- Contradictions between examples and rules, and between `SKILL.md` files and their references or Codex metadata, in `audit`, `ponytail`, `ponytail-review`, `test-driven-development`, `subagent-specialist`, `agents-md-improver`, `writing-skills`, `brainstorming`, `branding`, `motion-graphics`, `naming`, `playful-tone`, `caveman`, and `caveman-commit`.
