# Edges to Check

Where code that handles input from outside its control breaks. Check each edge the change touches while writing it.

- **Text placed into another language** (HTML, XML, Markdown, YAML, JSON, shell, URLs, regex, inline scripts): use its serializer, or escape for that exact context, and test with its metacharacters. Match prefixes with a boundary: `/callback` must not accept `/callback.evil`.
- **Present but absent values:** decide per field whether a key set to `undefined`, `None`, or `nil` means omitted, clear, or invalid, and test that call shape. A falsy check rejects legitimate `0` and `""`.
- **Stored data that could not be read:** when the read throws and the code falls back to defaults, save nothing over the stored data until a read succeeds, because the next save would replace everything stored with the defaults plus one change. Data that was read but cannot be parsed is replaced only after a copy of the original is kept, or when it is a cache the code can rebuild.
- **Records a new rule would remove:** when stored data already breaks a new rule, such as two contacts with one phone number, reading and saving keep every record as stored; the new rule only refuses new violations. Removing or merging the existing ones is a separate step that runs only after approval. A load that filters records hides them, and the next save deletes them without anyone approving it.
- **Caller-owned input:** copy what you keep, return copies of internal state, do not mutate the receiver in a builder, and apply fields you control after spreading caller input.
- **Unbounded work:** bound size, depth, and time, and avoid regexes with overlapping quantifiers and recursion on input depth. Pair every listener, timer, and child process with its teardown, and stop the whole process tree of each child you started by its process ID. Never stop processes by program name (`taskkill /IM node.exe`, `pkill node`): that also stops processes that are not yours. Re-check that the result is still wanted after every await.
- **Paths:** find the program's own bundled files from the module's location, not the current directory, and resolve paths a person passes from the working directory. A message to the person running the program about a missing path names the resolved path and gives advice that matches how it was resolved: never "run it from the project root" for a path found from the module. Require a path to stay inside a root only where its contract confines it, such as a stored or shared path that names a file to serve or delete. Write output to a new location and replace the old only after success, so a failed run leaves the last good output; delete only files the program created.
- **Batches:** when one item of many fails, such as one file a cleanup cannot delete, report it by name, continue with the rest unless they depend on it, and fail at the end with how many failed, through the boundary's failure contract: a CLI exits non-zero, a library throws or returns an aggregate error. Test a run where one item fails in the middle.
- **Access:** when code reads or changes records that belong to someone, check on the server that the caller may access each record, and test that another user is refused.
- **Failures at the entry point:** every failure the change adds, including the errors library parsers raise on bad input such as a URL, date, or number, follows the boundary's failure contract, even when older failures in the same path do not: a CLI prints one line and exits non-zero, an HTTP handler returns the matching status with no internals, and a library throws or returns its documented error type. Never a stack trace for the person. Catch parser errors where the input enters. The message names the rule and the value, with secrets removed: a database URL without its password. Generated output never carries credentials either.
- **Collisions:** when inputs become names, URLs, IDs, paths, or keys, two can become the same, including after case folding or normalization. Fail naming both instead of letting one replace the other.
- **Platform:** pass an explicit locale and time zone, expect case-insensitive paths on Windows and macOS, and parse dates and numbers before sorting or comparing them.
