# 0.2.0

## Added

- **ICU messages.** `t("welcome", { name: "Ana" })` fills `{name}` in the text, and a text can format its values: `{amount, number}`, `{when, date, long}`, `{count, plural, =0 {…} one {# item} other {# items}}`, `{n, selectordinal, …}`, and `{gender, select, …}`. Formatting follows the language of the text. An argument without a value is left as written. See [Put values into text](../translations.md#put-values-into-text).
- **Formatters.** `formatNumber`, `formatDate`, `formatRelativeTime`, and `formatList` format values for the active locale with `Intl`.
- **`timeZone`** on `createI18n` sets the time zone of dates and times in messages and `formatDate`'s default, so a server renders the reader's day rather than its own. See [Time zones](../translations.md#time-zones).
- **`has(key)`** tells whether a key exists, without calling `onMissingKey` or warning, and narrows a key built at runtime to one `t()` accepts. See [Typed keys](../translations.md#typed-keys).
- **Regional fallback.** A key missing from `pt-BR` comes from `pt` before the default locale, when both are configured. See [Regional variants](../translations.md#regional-variants).
- **Plurals.** A key can hold CLDR plural forms, such as `{ one: "{count} item", other: "{count} items" }`, and `t(key, { count })` picks the right one for the language with `Intl.PluralRules`. See [Plurals](../translations.md#plurals).
- **Typed keys.** Keys are inferred from what `loadLocale` returns, so a misspelled key fails to compile. `TranslationKey<typeof en>` names the key type for your own helpers. With an `as const` dictionary, `t()` also requires each message's values with the type its format needs. See [Typed values](../translations.md#typed-values).
- **`t`**, a short alias of `translate`, and every manager method keeps working when pulled off the manager, as in `export const { t } = i18n`.
- **`matchLocale(preferences)`** picks the best supported locale for a list of language tags, such as `pt` for `pt-BR`. Servers can now resolve `Accept-Language` the way the browser binding resolves `navigator.languages`.
- **`subscribe(listener)`** calls `listener` after every language change and returns a function that stops it, for framework stores such as React's `useSyncExternalStore`.
- **`onMissingKey(key, locale)`** receives every key missing from all dictionaries, in place of the default warning. Throw from it to fail tests on missing keys.
- **Translated paths.** `pathnames` on `createLocaleRouting` gives each locale its own words, so the about page can be `/pt/sobre`: `{ "/about": { pt: "/sobre" }, "/products/:id": { pt: "/produtos/:id" } }`. `parse()` reads a translated path back to the canonical path your app routes on, and `localize()` builds it. Mistakes in the table, such as two pages with the same path in one language, throw when routing is created. A last `:name*` segment matches the rest of the path, such as `/docs/:path*`. See [Translate paths](../localized-urls.md#translate-paths).
- **`localePrefix: "when-ambiguous"`** drops the locale prefix from a translated path whose words belong to one language only, so the about page can be just `/sobre`, while `/pt` and `/pt/blog` keep theirs. `localize()` throws a `RangeError` when the path it builds would open another page, such as an English page the table doesn't list at `/sobre`. See [Drop the prefix](../localized-urls.md#drop-the-prefix).
- **A default text direction.** `getLocaleDirection` is now optional; without it, Arabic, Hebrew, Persian, Urdu, and other right-to-left languages and scripts get `rtl`.
- Guides for writing translations, browser apps, server rendering and static builds, localized URLs, and troubleshooting, and a generated API reference.

## Changed

- **Breaking.** `t()` and `translate()` return a `string`, never `undefined`. A key missing from every dictionary returns the key, trimmed, such as `"home.subtitle"`, so the gap is visible on screen.
- **Breaking.** `init()` resolves `void` instead of `true` or `false`, like `setLocale()`. Read `i18n.locale` or `i18n.isReady` to see what was applied.
- **Breaking, types only.** When `loadLocale` returns a typed dictionary, `t()` accepts only its keys, so a key built at runtime, such as ``t(`errors.${code}`)``, no longer compiles.
- **Breaking, types only.** Only `locales` sets the locale type; `defaultLocale` and a callback parameter typed `string`, such as `loadLocale: (locale: string) => …`, no longer widen it. A configuration kept in a variable without `as const` on `defaultLocale` is now a compile error, where before it silently accepted any string as a locale.
- **Breaking.** `createLocaleRouting` takes `localePrefix` instead of `prefixDefaultLocale`: `"always"` for `true`, `"except-default"` for `false`, or the new `"when-ambiguous"`.
- **Breaking.** `localize()` and `localizeAll()` throw a `RangeError` when the path they build would be longer than 8,192 characters, where they returned a path that `parse()` rejects.
- **Breaking.** `parse()` returns `undefined` for a path no link leads to, such as `/pt/en/about`, so it can answer 404 and `localize(parse(path).pathname, …)` never throws.
- **Breaking.** An apostrophe before `{` or `}`, and `''`, now quote text, as ICU does, and a text with invalid ICU syntax, such as an unclosed `{`, logs a warning. A literal brace is written `'{'`.

## Migrating from 0.1.0

1. **Remove the fallbacks after `t()`.** `t(key) ?? ""` and `t(key) ?? key` still work but are no longer needed. Code that checked `t(key) === undefined` to detect a missing key never matches now; use `onMissingKey` instead.
2. **Stop reading `init()`'s result.** Replace `if (await i18n.init()) { … }` with `await i18n.init(); if (i18n.isReady) { … }`. A stale `init()`, superseded by a later call, resolves without applying, so compare `i18n.locale` when the outcome matters.
3. **Check or cast keys built at runtime.** Where TypeScript now rejects a computed key, check it with `i18n.has(key)`, or, when you know it exists, cast it with `as TranslationKey<typeof en>`, as in [Typed keys](../translations.md#typed-keys).
4. **Mark a separate configuration's default locale `as const`.** Fix `Type 'string' is not assignable to type '"en" | "pt"'` at `createI18n(config)` or `createLocaleRouting(config)` with `defaultLocale: "en" as const`.
5. **Replace `prefixDefaultLocale`.** In `createLocaleRouting`, `prefixDefaultLocale: true` becomes `localePrefix: "always"`, and `false` becomes `localePrefix: "except-default"`. In a configuration kept in a variable, add `as const`.
6. **Quote literal braces.** A text that shows `{` or `}` without meaning a value, such as a code sample, needs `'{'` and `'}'`. Run the message check in [Find untranslated keys](../translations.md#find-untranslated-keys) to find them.
7. **Optionally, drop `getLocaleDirection: () => "ltr"`.** The default gets right-to-left languages right; keep the option only to override it.
