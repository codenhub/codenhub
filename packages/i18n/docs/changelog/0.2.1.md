# 0.2.1

## Added

- A guide to [detecting the visitor's language on a static site](../localized-urls.md#detect-the-language-on-a-static-site), where no server sees `Accept-Language`: an inline redirect that runs before first paint, honors the language the browser binding saved, and never redirects a link from your own site or a prefixed URL.

## Changed

- `parse()` returns `undefined` for a path routing refuses, such as `//wp-login.php`, a dot segment, an encoded slash, or one longer than 8,192 characters, where it threw a `TypeError`. A request can carry any of these, and the guide's handlers, which call `parse(url.pathname)` without a catch, answered them with a 500; they now get the 404 every other path that is no page gets. `parse()` still throws for a value that is not a URL's pathname, such as a full URL or a path with its query string, and `localize()` and `localizeAll()` still throw for every refused path. A `try` around `parse()` that answered 400 can go, or stay: it now only catches mistakes in the calling code.
- `has()` returns `false` for a string no dictionary can hold, such as one with a line break or longer than 1,000 characters, where it threw a `TypeError`, so ``has(`errors.${code}`)`` is safe with a `code` from a response or a query string. It still throws for a non-string, and `t()` still throws for an invalid key.
- A text with a stray `}` and no `{` or `'`, such as `a } b`, now logs the invalid-syntax warning that `it's a } b` already logged. The text shown is unchanged. Quote a literal brace as `'}'`.
- The package's npm homepage is its page on codenhub.dev.

## Fixed

- `formatDate(value, { timeZone: undefined })`, as options forwarded from a property often are, used the runtime's time zone instead of the manager's `timeZone`, so a server could show its own calendar day. A `timeZone` the options inherit, as from a class instance's defaults, no longer reuses a formatter made for another zone.
