# 0.5.0

## Added

- **`binding.switchToSystemLocale()`** forgets the saved locale and switches to the one detected from the browser right now, without saving it, so a "System" entry in your picker can undo a visitor's choice. When the detected locale fails to load, it rejects with the loader's `I18nError` and the page keeps its language; the saved choice is already forgotten, so the next visit detects again. See [Offer a "System" choice](../browser.md#offer-a-system-choice).
- **`binding.isUsingSystemLocale`** says whether to show "System" selected: `true` after a start with nothing chosen and after `switchToSystemLocale()`, `false` once your app applies a locale with `setLocale()` or `init()`.
- **`binding.subscribe()`** calls your function once after each change to what a picker shows, the language or `isUsingSystemLocale`, including a pick of the language already showing, which `i18n.subscribe()` doesn't report. Render a framework picker from it, as the [React example](../browser.md#offer-a-system-choice) does.
- **`parse()` returns `alternates`**, the page's URL in every language that has one, for language switchers and `hreflang` tags. A language whose URL would open another page is left out, where `localize()` throws, so an English product `/products/novo` next to a translated `/products/new` no longer makes the guide's switcher answer 500. See [Link to another language](../localized-urls.md#link-to-another-language).
- **`rich(key, values)`** returns a message as text and `{ tag, children }` parts, so a link or bold text inside a sentence stays one message a translator can reorder: `"Read the <link>terms</link>"` gives `["Read the ", { tag: "link", children: ["terms"] }]`. Map the parts to your framework's elements. Tags come only from the message, never from a value, and unbalanced tags warn once and return the text as `t()` shows it. See [Links and bold text inside a sentence](../translations.md#links-and-bold-text-inside-a-sentence).
- **A bigint is taken wherever a number is**, in `{n}`, `{n, number}`, `plural`, `selectordinal`, `select`, and a plural group's `count`. It is formatted without losing digits and selects its plural form exactly, so `10n ** 20n + 22n` in an English ordinal reads "…22nd".
- If your code implements `I18n`, `BrowserI18nBinding`, or `LocaleRouting`, or builds `parse()` results, as a test double might, add the new members, or build the double from the real thing. A test that compares a `parse()` result with `toEqual({ locale, pathname })` now needs `alternates` too, or `toMatchObject`.

## Changed

- **`localize()` reads every path as canonical, and throws a `RangeError` for one that starts with a locale.** A prefixed path was read as that locale's URL, so with Burmese, `my`, configured, `localize("/my/orders", "en")` linked to the Burmese `/orders`. To switch a URL's language, pass `parse(url).pathname`, as the guide does; a page whose path starts with a locale code needs another path, since no URL leads to it. See [Link to another language](../localized-urls.md#link-to-another-language).
- **Every segment is normalized as RFC 3986 says**, parameters and unlisted segments included. `localize("/products/café", "en")` returns `/products/caf%C3%A9`, where it wrote a raw `é` into the link, and `parse("/pt/produtos/café").pathname` is `/products/caf%C3%A9` too, so two spellings of one page give one `pathname`. A segment is normalized as RFC 3986 says: an escaped unreserved character such as `%61` is decoded, other escapes are written in upper case, and an escaped reserved character stays escaped, so `c%2B%2B` and `c++` stay two pages. That also encodes `|`, `[`, and `]`, which a URL's pathname leaves raw. A lone surrogate, which is not text, is written as `%EF%BF%BD`, as a URL writes it. A canonical redirect that compares the request with `localize(route.pathname, …)` now redirects a hand-typed `/café` once, to the encoded form. Code that compares `parse().pathname` with a path of its own needs that path in the same encoded form, as `localize()` returns it; decoding `pathname` with `decodeURI()` instead fails for a segment such as `%3F` or `%2B`, which it leaves encoded.
- **A regional locale falls back to the configured locale of its likely script** after its parents: `zh-HK` reads `zh-Hant`, and `sr-ME` reads `sr-Latn`, where both fell back to the default. The fallback locale loads with it.
- **`matchLocale()` reads `_` as `-`**, so `pt_BR` and `zh_Hant_TW`, as an OS or a database writes them, match `pt-BR` and `zh-Hant-TW`, where they matched nothing.
- **`resolveLocale()` reads `_` as `-`** too, so `pt_BR` from a cookie or a back end resolves to `pt-BR`, where it returned `undefined`.
- **The default missing-key warning is logged once per process for each locale and key**, shared by every manager, where each manager kept its own record. A server with a manager per request logged one missing word once for every visitor. A test that expects each new manager to warn again passes `onMissingKey` instead.
- **An invalid message warns once per process for each locale and text**, shared by every manager, as a missing key does.
- **`data-i18n` and `data-i18n-<attribute>` keep the HTML's value for a message that needs values**, one with a placeholder, a plural, or a select, and warns once per key, where it wrote the message as written, such as `Hello {name}`, without a warning. Render that text with `t()`.
- **`data-i18n` and `data-i18n-<attribute>` set `lang` on text from a fallback locale's dictionary**, so a screen reader reads an English fallback on a French page in English. The locale is compared with the language the element has without the mark, its own `lang` or its nearest ancestor's, so a French text in a widget under `<html lang="en">` is marked `fr` with `syncDocument: false` too. An element is marked only when every key it shows comes from that one locale, so a button with French text and an English `title` isn't. The binding restores the element's own `lang` when the text is translated again, unless your code has changed that `lang`, which then stays yours to update.
- **`data-i18n-title` on a `<style>` or a `<link rel="stylesheet">` is skipped with a warning**, since their `title` names a style sheet set and translating it would change which styles apply.
- **A configuration error quotes a received string**, so `localePrefix: "as-needed"` reads `Expected …, received "as-needed"`, where it read `received string`.
- **`matchLocale()` skips a preference longer than 255 characters**, as it skips one that isn't a string. A 16 KB `Accept-Language` entry cost about 25 ms a match.
- **`data-i18n` skips `iframe`, `noembed`, `noframes`, `plaintext`, and `xmp`**, as it skips `script` and `style`, with a warning. Serializing the page writes their text without escaping, so a translation in one of them could become markup in server-rendered or prerendered HTML.
- **Only the content of those elements is skipped.** An element inside one of them, which only script can put there, is skipped whole, with a warning, and so is one inside a `<template>` or a `<noscript>`. Their own `data-i18n-<attribute>` keys are translated, so an `<iframe>`'s `data-i18n-title`, the name a screen reader gives an embedded video or map, follows the language. That includes `<template>` and `<noscript>`, whose attributes 0.4.0 left untranslated.
- **`initializeBrowserI18n()` throws a `TypeError` when there is no global event target**, before touching the manager, where it initialized the manager and then rejected.
- **`t()` takes values typed by an interface or a class**, such as a `User`, where only object literals and index-signature types compiled. `t()` has a second type parameter for the values; a call that passes the key's type argument, `t<"cart.title">(…)`, is unaffected.
- **A visitor who never chose a language follows the browser mid-visit.** While `isUsingSystemLocale` is `true`, a `languagechange` event switches to the newly detected locale without saving it, where the page kept its language until a reload. A visitor's pick still loading when the event arrives is kept. A load that fails warns, "Could not switch to the detected locale", and keeps the current language. You need do nothing; a visitor who chose a language, or a start with an explicit `locale`, is not affected.
- **A `setLocale()` to the language already showing is saved**, like any other choice, where nothing was saved. A visitor who picks English while English was detected has chosen it, and keeps it after changing their browser's language.
- `disconnect()` also stops following the browser's language and calling `binding.subscribe()` listeners, and drops a switch to a detected locale still loading. A `setLocale()` still loading still applies.
- **The guide's language switcher and `hreflang` tags read `route.alternates`** instead of calling `localize()` on a path from the request. Do the same in yours. The `x-default` tag is left out when the default locale has no URL for the page. A static build still uses `localizeAll()`, which throws on a clash, so the build finds it.
- **A JSON dictionary's plural group needs a numeric `count` in `t()`.** With forms typed `string`, as from a JSON import, `t("cart.items")` compiled and then showed `cart.items`.
- **Under `localePrefix: "when-ambiguous"`, only paths read without a prefix keep a translated path's prefix**: the default locale's paths, and the other translated paths that drop theirs. A Spanish `/:tag`, which keeps `/es`, no longer keeps the prefix on the Portuguese `/sobre`. Some URLs lose their prefix, so redirect the old `/pt/…` form as the guide shows; `parse()` still accepts it.
- **Routing errors quote the value and name the rule it breaks**, such as `[I18n] pathname "/help/../admin" must not contain a dot segment, . or ..` and `[I18n] Unsupported locale "fr".`, as the manager's errors do. They replace "must be a valid absolute application pathname" and "must not contain dot segments". A configuration error for a table entry reads `Must start with /` and similar. A value that doesn't start with `/` isn't quoted, and one with a query or fragment is quoted up to its `?` or `#`, since a full URL can carry a credential there.
- **`localize()`'s "would be read as" `RangeError` names the URL it would build**, such as `"/pt/produtos/novo"`, and no longer tells you to pass `parse().pathname` when that is what you passed. Code that matches the text after the `;` needs updating.
- **Paths have at most 100 segments.** `parse()` returns `undefined` for a longer one, and `localize()` throws a `TypeError` for one, or a `RangeError` when its prefix or translated words take it past 100, as for 8,192 characters. A request made of thousands of one-letter segments, such as `/a/a/a/…`, cost about 40 ms a `parse()` with 20 locales, so anyone could keep a server busy with it. The `RangeError` reads "would be longer than 8,192 characters or 100 segments", and gives the length the URL would have.
- **A number in a plain `{name}` is formatted for the reader**, as `{name, number}` does and as ICU MessageFormat does, so `"{count} items"` with `1234` reads "1,234 items", or "1.234 itens" in Portuguese, where it read "1234 items" in every language. A message that wants the digits as written, such as an order number, takes a string: `t("order", { id: String(id) })`. A number in a message that is not valid ICU syntax is formatted too.
- **`loadLocale` must accept every configured locale.** A loader typed for fewer, such as `(locale: keyof typeof dictionaries)` before every dictionary exists, no longer compiles, where `init()` rejected at runtime.
- **`initializeBrowserI18n`'s `locale` must be a configured locale.** `initializeBrowserI18n({ i18n, locale: "fr" })` on a manager without `fr` no longer compiles, where it rejected at runtime.
- **`t()` accepts any values for a message it prints as written**: one with an unknown style, such as `{n, number, currency}`, a `plural` or `select` without `other`, or `'#` quoting a brace inside a plural. The types required values the runtime never filled in.
- **`t()` takes any key when the loader returns `Record<string, unknown>`**, where no key compiled.
- **`t(key, values)` throws a `TypeError` when `values` is `null` or a primitive.** `null` failed with a native error from inside the package, and a string was ignored.
- **Errors that name a dictionary key, a locale, a path, or a configuration property quote it**, with line breaks escaped, and cut it after 100 characters. A test that matches such a message for an unusual key or locale may need updating; ordinary ones read the same. Routing errors do the same for a pathname.
- **The `data-i18n` warnings name the key and the element.** "Skipping translation because data-i18n contains an invalid key", "translated elements must be leaves", and "the element can run, hide, or reparse its text as HTML" now quote the key, and pass the element after the message, so the browser console points to it. The message is the second argument, after a `"%s"` format, so a key such as `%o` is shown as written. A test that expects the exact message, or one argument, needs updating.
- **`formatRelativeTime()` and `formatList()` reuse their `Intl` formatters**, several times faster in a list of "3 days ago" labels.
- **Creating a manager and `matchLocale()` are about 5 times faster with many locales**, since locale data is computed once per process.
- **`parse()` stops at the first route that matches**, where it tried every route of the path's shape: a table of 2,000 deep routes reads a path in about half the time.

## Fixed

- **The server-rendering guide no longer overwrites a visitor's choice.** It passed the server's `Accept-Language` match to the binding as `locale`, which the binding saves, so on a site without a locale in the URL a visitor who picked Portuguese got English saved over it on every page load. The guide now keeps the choice in a cookie that the server reads and `binding.subscribe()` writes, and starts the binding without `locale` when there is none. If you followed it, see [Hand the locale to the browser](../server-rendering.md#hand-the-locale-to-the-browser).
- **Two bindings whose roots overlap no longer hang the page.** Each rewrote the other's text, forever. A binding now skips text it wrote itself; the guide says to keep roots apart.
- **A loader type made of `Partial<typeof en>` checks values again**, where it accepted any values for every key.
- **A visitor following the system follows a `languagechange` that arrived while their own pick was loading**, once that pick fails, where the page kept the old language until the next event.
- **The shared message cache counts what each message keeps in memory**, not only its length, so a dictionary of messages full of placeholders or `#` can no longer keep hundreds of megabytes alive on a server.
- **`matchLocale()` ignores a preference's extensions**, so `es-u-hc-h23`, which a browser may send, matches `es-ES` as `es` does, where it matched the first Spanish locale listed, such as `es-419`.
- **A language with no likely script matches and falls back to its parent**, so `nah-MX` matches and falls back to `nah`, where it matched nothing and fell back to the default.
- **`t()` leaves a date or time as written for a timestamp past what a `Date` holds**, such as `1e16`, where it threw a `RangeError`, and formats a `Date` from another realm, such as an iframe, where it left it as written.
- **`parse()` and `localize()` read a percent-encoded locale prefix**, so `/%70t/sobre` is Portuguese, as `/pt/sobre` is, and `/pt/%65n/about` is refused, as `/pt/en/about` is.
- **A `binding.subscribe()` listener that calls `disconnect()` stops the listeners after it**, and `disconnect()` releases every listener.
- **A key over 10,000 characters is refused before it is trimmed**, as documented, with an error that names that limit.
- **A key with surrounding whitespace is no longer refused** by `t()`, `has()`, or `data-i18n` when it is within 1,000 characters once trimmed.
- **Creating a routing with `localePrefix: "when-ambiguous"` takes linear time** in tables whose translated paths start with a parameter: 20,000 such routes took about 17 s and take about 0.4 s. Which paths drop the prefix is unchanged.
- **`localizeAll("/help/:path*")` translates through the table's catch-all.** With `/help/:id` also listed, it returned the parameter route's form, such as `/pt/ajuda/artigo/:path*`, and a router registered it for the wrong pages.
- **`parse()` costs about the same per locale whatever the path**: with 100 locales, a path near the 8,192-character limit took up to 27 ms and takes under 2 ms.
- **`data-i18n` skips a customized built-in created from script**, such as `document.createElement("button", { is: "x-button" })`, which has no `is` attribute, as it skips `<button is="x-button">`.
- **With `observe`, text other code writes over a keyed element no longer becomes its fallback.** The binding writes the translation back, and the HTML's text stays the one shown for a language without the key.
- The docs say that a plural group `has()` finds needs `count` in `t()`.
- The docs say that the binding never enters a shadow root, a custom element's or a plain element's.
