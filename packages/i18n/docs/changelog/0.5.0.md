# 0.5.0

## Added

- **`binding.switchToSystemLocale()`** forgets the saved locale and switches to the one detected from the browser right now, without saving it, so a "System" entry in your picker can undo a visitor's choice. When the detected locale fails to load, it rejects with the loader's `I18nError` and the page keeps its language; the saved choice is already forgotten, so the next visit detects again. See [Offer a "System" choice](../browser.md#offer-a-system-choice).
- **`binding.isUsingSystemLocale`** says whether to show "System" selected: `true` after a start with nothing chosen and after `switchToSystemLocale()`, `false` once your app applies a locale with `setLocale()` or `init()`.
- **`binding.subscribe()`** calls your function once after each change to what a picker shows, the language or `isUsingSystemLocale`, including a pick of the language already showing, which `i18n.subscribe()` doesn't report. Render a framework picker from it, as the [React example](../browser.md#offer-a-system-choice) does.
- **`parse()` returns `alternates`**, the page's URL in every language that has one, for language switchers and `hreflang` tags. A language whose URL would open another page is left out, where `localize()` throws, so an English product `/products/novo` next to a translated `/products/new` no longer makes the guide's switcher answer 500. See [Link to another language](../localized-urls.md#link-to-another-language).
- **`rich(key, values)`** returns a message as text and `{ tag, children }` parts, so a link or bold text inside a sentence stays one message a translator can reorder: `"Read the <link>terms</link>"` gives `["Read the ", { tag: "link", children: ["terms"] }]`. Map the parts to your framework's elements. A tag's name takes `-` after its first character, as in `<help-link>`. Tags come only from the message, never from a value or from quoted text such as `'{<b>}'`, and unbalanced tags warn once and return the text as `t()` shows it. See [Links and bold text inside a sentence](../translations.md#links-and-bold-text-inside-a-sentence).
- **A bigint is taken wherever a number is**, in `{n}`, `{n, number}`, `plural`, `selectordinal`, `select`, and a plural group's `count`. It is formatted without losing digits and selects its plural form exactly, so `10n ** 20n + 22n` in an English ordinal reads "…22nd".
- **`select` takes a boolean**, picking the option named `true` or `false`, or `other`: `{isAdmin, select, true {Admin} other {Member}}` shows "Admin" for `{ isAdmin: true }`, where it showed the message's source. The types accept a boolean for `select` only; in a plain `{isAdmin}` it stays as written.
- **`initializeBrowserI18n`'s `storage` option** saves the visitor's choice somewhere other than `localStorage`, such as a cookie your server reads, through `get()`, `set(locale)`, and `remove()`. A choice read from it is matched and falls back when its dictionary fails to load, as a saved one does, which a choice passed as `locale` can't. A value that isn't a configured locale counts as nothing saved, and a method that throws warns. Passing it with `storageKey` or `persistLocale: false` rejects with a `TypeError`. See [Hand the locale to the browser](../server-rendering.md#hand-the-locale-to-the-browser).
- If your code implements `I18n`, `BrowserI18nBinding`, or `LocaleRouting`, or builds `parse()` results, as a test double might, add the new members, or build the double from the real thing. A test that compares a `parse()` result with `toEqual({ locale, pathname })` now needs `alternates` too, or `toMatchObject`.

## Changed

- **`localize()` reads every path as canonical, and throws a `RangeError` for one that starts with a locale.** A prefixed path was read as that locale's URL, so with Burmese, `my`, configured, `localize("/my/orders", "en")` linked to the Burmese `/orders`. To switch a URL's language, pass `parse(url).pathname`, as the guide does; a page whose path starts with a locale code needs another path, since no URL leads to it. See [Link to another language](../localized-urls.md#link-to-another-language).
- **Every segment is normalized as RFC 3986 says**, parameters and unlisted segments included. `localize("/products/café", "en")` returns `/products/caf%C3%A9`, where it wrote a raw `é` into the link, and `parse("/pt/produtos/café").pathname` is `/products/caf%C3%A9` too, so two spellings of one page give one `pathname`. A segment is normalized as RFC 3986 says: an escaped unreserved character such as `%61` is decoded, other escapes are written in upper case, and an escaped reserved character stays escaped, so `c%2B%2B` and `c++` stay two pages. That also encodes `[`, `]`, `|`, and `^`, which a URL's pathname can leave raw, depending on the runtime. A lone surrogate, which is not text, is written as `%EF%BF%BD`, as a URL writes it. A canonical redirect that compares the request with `localize(route.pathname, …)` now redirects a hand-typed `/café` once, to the encoded form. Code that compares `parse().pathname` with a path of its own needs that path in the same encoded form, as `localize()` returns it; decoding `pathname` with `decodeURI()` instead fails for a segment such as `%3F` or `%2B`, which it leaves encoded.
- **A regional locale falls back to the configured locale of its likely script** after its parents: `zh-HK` reads `zh-Hant`, and `sr-ME` reads `sr-Latn`, where both fell back to the default. The fallback locale loads with it.
- **`matchLocale()` reads `_` as `-`**, so `pt_BR` and `zh_Hant_TW`, as an OS or a database writes them, match `pt-BR` and `zh-Hant-TW`, where they matched nothing.
- **`resolveLocale()` reads `_` as `-`** too, so `pt_BR` from a cookie or a back end resolves to `pt-BR`, where it returned `undefined`.
- **The default missing-key warning is logged once per process for each locale and key**, shared by every manager, where each manager kept its own record. A server with a manager per request logged one missing word once for every visitor. A test that expects each new manager to warn again passes `onMissingKey` instead.
- **An invalid message warns once per process for each locale, key, and text**, shared by every manager, as a missing key does, so an edited text warns again. Both records keep a bounded amount of memory, about 1,000 typical keys, and remember a message by a hash of its text, not the text itself.
- **Names in a message take letters and digits in any script**: an argument such as `{año}`, a select option such as `niño {…}`, and a tag such as `<énfasis>` or `<help-link>`, where only ASCII letters, digits, and `_` were read: such a message was invalid syntax, or its tag was text. A tag also takes `-` after its first character, as a select key takes it anywhere. The types check values only for ASCII names; a message with another name accepts any values.
- **`data-i18n` and `data-i18n-<attribute>` keep the HTML's value for a message that needs values**, one with a placeholder, a plural, or a select, and warns once per key, where it wrote the message as written, such as `Hello {name}`, without a warning. Render that text with `t()`.
- **`data-i18n` and `data-i18n-<attribute>` set `lang` on text from a fallback locale's dictionary**, so a screen reader reads an English fallback on a French page in English. The locale is compared with the language the element has without the mark, its own `lang` or its nearest ancestor's, so a French text in a widget under `<html lang="en">` is marked `fr` with `syncDocument: false` too. An element is marked only when every key it shows comes from that one locale, so a button with French text and an English `title` isn't. The binding restores the element's own `lang` when the text is translated again, unless your code has changed that `lang`, which then stays yours to update.
- **`data-i18n-title` on a `<style>` or a `<link rel="stylesheet">` is skipped with a warning**, since their `title` names a style sheet set and translating it would change which styles apply.
- **A configuration error quotes a received string**, so `localePrefix: "as-needed"` reads `Expected …, received "as-needed"`, where it read `received string`.
- **`createI18n()` and `createLocaleRouting()` reject a locale that `Intl` rejects**, such as `en-US-US` or `en-GB-oed`, with `locales[1]: Must be a language tag Intl accepts, …`, where it was accepted, and in routing became a URL prefix, so a typo served `/en-US-US/…` without an error. A private-use tag, such as `x-pirate`, is still accepted, and matches only exactly, where a locale `Intl` rejected matched by its language subtag. A configuration that throws now fixes the tag, or uses `x-` for a locale of its own.
- **`matchLocale()` skips a preference longer than 255 characters**, as it skips one that isn't a string. A 16 KB `Accept-Language` entry cost about 25 ms a match.
- **`data-i18n` skips `iframe`, `noembed`, `noframes`, `plaintext`, and `xmp`**, as it skips `script` and `style`, with a warning. Serializing the page writes their text without escaping, so a translation in one of them could become markup in server-rendered or prerendered HTML.
- **Only the content of those elements is skipped.** An element inside one of them, which only script can put there, is skipped whole, with a warning, and so is one inside a `<template>` or a `<noscript>`. Their own `data-i18n-<attribute>` keys are translated, so an `<iframe>`'s `data-i18n-title`, the name a screen reader gives an embedded video or map, follows the language. That includes `<template>` and `<noscript>`, whose attributes 0.4.0 left untranslated.
- **`initializeBrowserI18n()` rejects with a `TypeError` when there is no global event target**, before touching the manager, where it initialized the manager and then rejected.
- **`t()` takes values typed by an interface or a class**, such as a `User`, where only object literals and index-signature types compiled, and checks only the values the message uses. Any other value may have any type, in an interface or an object literal, so a `User` with an `isAdmin: boolean` is taken whole; a missing or wrongly typed value the message uses still fails to compile. `t()` has a second type parameter for the values; a call that passes the key's type argument, `t<"cart.title">(…)`, is unaffected.
- **A visitor who never chose a language follows the browser mid-visit.** While `isUsingSystemLocale` is `true`, a `languagechange` event switches to the newly detected locale without saving it, where the page kept its language until a reload. A visitor's pick still loading when the event arrives is kept. A load that fails warns, "Could not switch to the detected locale", and keeps the current language. A picker that sets its value only after its own switches keeps showing the old language; render it from `binding.subscribe()`, as [Let visitors switch languages](../browser.md#let-visitors-switch-languages) does. A visitor who chose a language, or a start with an explicit `locale`, is not affected.
- **A `setLocale()` to the language already showing is saved**, like any other choice, where nothing was saved. A visitor who picks English while English was detected has chosen it, and keeps it after changing their browser's language.
- `disconnect()` also stops following the browser's language and calling `binding.subscribe()` listeners, and drops a switch to a detected locale still loading. A `setLocale()` still loading still applies.
- **The guide's language switcher and `hreflang` tags read `route.alternates`** instead of calling `localize()` on a path from the request. Do the same in yours. The `x-default` tag is left out when the default locale has no URL for the page, and its default locale comes from the constants the guide's routing module exports, not a second copy that drifts when the default changes. A static build still uses `localizeAll()`, which throws on a clash, so the build finds it.
- **A JSON dictionary's plural group needs a numeric `count` in `t()`.** With forms typed `string`, as from a JSON import, `t("cart.items")` compiled and then showed `cart.items`.
- **Under `localePrefix: "when-ambiguous"`, only paths read without a prefix keep a translated path's prefix**: the default locale's paths, and the other translated paths that drop theirs. A Spanish `/:tag`, which keeps `/es`, no longer keeps the prefix on the Portuguese `/sobre`. Some URLs lose their prefix, so redirect the old `/pt/…` form as the guide shows; `parse()` still accepts it.
- **Routing errors quote the value and name the rule it breaks**, such as `[I18n] pathname "/help/../admin" must not contain a dot segment, . or ..` and `[I18n] Unsupported locale "fr".`, as the manager's errors do. They replace "must be a valid absolute application pathname" and "must not contain dot segments". A configuration error for a table entry reads `Must start with /` and similar. Nothing a URL reads as user info, a query, or a fragment is quoted, since a full URL can carry a credential there: a value that doesn't start with `/`, or that a URL reads as starting another host, such as `//host` or `/\host`, even with a tab or line break between the slashes, isn't quoted, and one with a query or fragment is quoted up to the first `?` or `#`, which the message names. An unsupported locale passed to `localize()` or to the manager is quoted the same way, so `https://user:secret@host` reads `[I18n] Unsupported locale, not quoted since it reads as a URL.`
- **`localize()`'s "would be read as" `RangeError` names the URL it would build**, such as `"/pt/produtos/novo"`, and no longer tells you to pass `parse().pathname` when that is what you passed. Code that matches the text after the `;` needs updating.
- **Paths have at most 100 segments.** `parse()` returns `undefined` for a longer one, and `localize()` throws a `TypeError` for one, or a `RangeError` when its prefix or translated words take it past 100, as for 8,192 characters. A request made of thousands of one-letter segments, such as `/a/a/a/…`, cost about 40 ms a `parse()` with 20 locales, so anyone could keep a server busy with it. The `RangeError` reads "would be longer than 8,192 characters or 100 segments", and gives the length the URL would have.
- **A number in a plain `{name}` is formatted for the reader**, as `{name, number}` does and as ICU MessageFormat does, so `"{count} items"` with `1234` reads "1,234 items", or "1.234 itens" in Portuguese, where it read "1234 items" in every language. A message that wants the digits as written, such as an order number, takes a string: `t("order", { id: String(id) })`. A number in a message that is not valid ICU syntax is formatted too.
- **`loadLocale` must accept every configured locale.** A loader typed for fewer, such as `(locale: keyof typeof dictionaries)` before every dictionary exists, no longer compiles, where `init()` rejected at runtime.
- **`initializeBrowserI18n`'s `locale` must be a configured locale.** `initializeBrowserI18n({ i18n, locale: "fr" })` on a manager without `fr` no longer compiles, where it rejected at runtime.
- **`t()` accepts any values for a message it prints as written**: one with an unknown style, such as `{n, number, currency}`, a `plural` or `select` without `other`, or `'#` quoting a brace inside a plural. The types required values the runtime never filled in.
- **`t()` takes any key when the loader returns `Record<string, unknown>`**, where no key compiled.
- **An `init()` that switches a ready manager to another locale also dispatches `locale-change`**, after `ready`, with `previousLocale`, where it dispatched only `ready`, so a `locale-change` listener missed the switch. `subscribe()` listeners are still called once for it. The first `init()` dispatches only `ready`, and an `init()` with the locale already active dispatches no `locale-change`.
- **`t(key, values)` throws a `TypeError` when `values` is `null` or a primitive.** `null` failed with a native error from inside the package, and a string was ignored.
- **Errors that name a dictionary key, a locale, a path, or a configuration property quote it**, with line breaks escaped, and cut it after 100 characters. A test that matches such a message for an unusual key or locale may need updating; ordinary ones read the same. Routing errors do the same for a pathname, and so do the warnings for invalid syntax and unbalanced tags, which name an unknown type, style, plural form, repeated option, or tag.
- **The `data-i18n` warnings name the key and the element.** "Skipping translation because data-i18n contains an invalid key", "translated elements must be leaves", and "the element can run, hide, or reparse its text as HTML" now quote the key, and pass the element after the message, so the browser console points to it. The message is the second argument, after a `"%s"` format, so a key such as `%o` is shown as written. A test that expects the exact message, or one argument, needs updating.
- **`i18n.subscribe` and `binding.subscribe` are typed as function properties**, not methods, so a lint rule against unbound methods, such as `@typescript-eslint/unbound-method`, accepts `useSyncExternalStore(binding.subscribe, …)`. Both were already bound at runtime. A test double that implements one as a method with a narrower listener type no longer compiles.
- **A `data-i18n` or `data-i18n-<attribute>` whose `onMissingKey` throws shows the HTML's value**, where it kept the translation of the earlier key or locale. The error is still reported.
- **`formatRelativeTime()` and `formatList()` reuse their `Intl` formatters**, several times faster in a list of "3 days ago" labels.
- **`matchLocale()` takes a few microseconds whatever the number of locales**, where it took about 160 µs a call with 20 locales and 770 µs with 100, since each locale's forms are computed once per manager, and likely subtags and canonical tags once per process. **Creating a manager is about 3 times faster** with 20 to 100 locales: about 55 µs with 20 and 240 µs with 100, where it took 160 µs and 780 µs. Measured on Node.js 26.13 with three preferences that match by likely subtags.
- **`parse()` stops at the first route that matches**, where it tried every route of the path's shape: a table of 2,000 deep routes reads a path in about half the time.

## Fixed

- **The server-rendering guide no longer overwrites a visitor's choice.** It passed the server's `Accept-Language` match to the binding as `locale`, which the binding saves, so on a site without a locale in the URL a visitor who picked Portuguese got English saved over it on every page load. The guide now keeps the choice in a cookie that the server reads and the binding reads, writes, and deletes through its new `storage` option, so a cookie choice that fails to load falls back as a saved one does, and a language the binding detects is never written. The server reads a choice you no longer list exactly, such as `pt-BR` once you list only `pt`, with `matchLocale()` after `resolveLocale()`, and the binding matches it the same way, so it isn't lost to the `Accept-Language` guess. If you followed it, see [Hand the locale to the browser](../server-rendering.md#hand-the-locale-to-the-browser).
- **Each `#` counts toward the 100 arguments one call fills**, and past them a `#` is written as `#`. A plural form of 99,970 `#` with `1e308` made one `t()` return 41 million characters, since only arguments were counted, so a fetched message could make a server allocate tens of megabytes per request.
- **An element moved inside a blocked element or a custom element after it was translated gets back its HTML text, attributes, and `lang`**, at the next language change, or at once with `observe`. Its translated `title` could otherwise become markup when the page was serialized and parsed again.
- **An `init()` that switches the locale on a bound manager translates the page once**, so `onMissingKey` is called once per missing key, where it ran twice.
- **The default direction is `rtl` for variants of a right-to-left script**: `Aran` (Arabic Nastaliq), `Syre`, `Syrj`, and `Syrn` (Syriac), and `Phlv` (Book Pahlavi), so `ur-Aran` is `rtl`, where it was `ltr`.
- **Two bindings whose roots overlap no longer hang the page.** Each rewrote the other's text, forever. A binding now skips text it wrote itself; the guide says to keep roots apart.
- **A loader type made of `Partial<typeof en>` checks values again**, where it accepted any values for every key.
- **A visitor following the system follows a `languagechange` that arrived while their own pick was loading**, once that pick fails, where the page kept the old language until the next event.
- **The shared message cache counts what each message keeps in memory**, not only its length, so a dictionary of messages full of placeholders or `#` can no longer keep hundreds of megabytes alive on a server.
- **`matchLocale()` ignores a preference's extensions**, so `es-u-hc-h23`, which a browser may send, matches `es-ES` as `es` does, where it matched the first Spanish locale listed, such as `es-419`.
- **A language with no likely script matches and falls back to its parent**, so `nah-MX` matches and falls back to `nah`, where it matched nothing and fell back to the default.
- **A locale falls back to a parent written under another code for its language**, such as a configured `iw` for `he-IL`, `he` for `iw-IL`, `in` for `id-ID`, or `no` for `nb-NO`, where it fell back to the default. Deprecated codes are read as `Intl` canonicalizes them, and `no` and `nb` count as one language, as in `matchLocale()`.
- **`t()` leaves a date or time as written for a timestamp past what a `Date` holds**, such as `1e16`, where it threw a `RangeError`, and formats a `Date` from another realm, such as an iframe, where it left it as written.
- **`parse()` and `localize()` read a percent-encoded locale prefix**, so `/%70t/sobre` is Portuguese, as `/pt/sobre` is, and `/pt/%65n/about` is refused, as `/pt/en/about` is.
- **A `binding.subscribe()` listener that calls `disconnect()` stops the listeners after it**, and `disconnect()` releases every listener.
- **A key over 10,000 characters is refused before it is trimmed**, as documented, with an error that names that limit.
- **A key with spaces around it is no longer refused** by `t()`, `has()`, or `data-i18n` when it is within 1,000 characters once trimmed. Spaces are trimmed, Unicode ones such as the no-break space included, and so are the byte order mark and the Unicode line and paragraph separators. A tab, a line feed, a carriage return, or any other ASCII control is still refused wherever it is in the key.
- **Creating a routing with `localePrefix: "when-ambiguous"` takes linear time** in tables whose translated paths start with a parameter: 20,000 such routes took about 17 s and take about 0.4 s. Which paths drop the prefix is unchanged.
- **`localizeAll("/help/:path*")` translates through the table's catch-all.** With `/help/:id` also listed, it returned the parameter route's form, such as `/pt/ajuda/artigo/:path*`, and a router registered it for the wrong pages.
- **`parse()` costs about the same per locale whatever the path**: with 100 locales, a path near the 8,192-character limit took up to 27 ms and takes under 2 ms.
- **An element inside a `<textarea>` or a `<title>` is skipped whole**, with a warning, as one inside an `<xmp>` is. Both read their content as text up to their end tag, so a translated attribute holding `</textarea><img onerror=…>` on an element that script put inside one became markup once the page was saved as HTML by a serializer that leaves `<` in attribute values, as jsdom's does, and read again. The text and attributes of a `<textarea>` or `<title>` itself are still translated.
- **A `data-i18n` or `data-i18n-<attribute>` key changed to an invalid one shows the HTML's value**, as a missing key does, where the element kept the translation of its earlier key. A blank key, one over the length limit, and one with an ASCII control are invalid, and the HTML's value comes back whether a later binding, an observed change, a language change, or moving the element back in reads the key.
- **`data-i18n` skips a customized built-in created from script**, such as `document.createElement("button", { is: "x-button" })`, which has no `is` attribute, as it skips `<button is="x-button">`.
- **With `observe`, text other code writes over a keyed element no longer becomes its fallback.** The binding writes the translation back, and the HTML's text stays the one shown for a language without the key.
- The docs say that a plural group `has()` finds needs `count` in `t()`.
- The docs say that the binding never enters a shadow root, a custom element's or a plain element's.
- The browser guide's language picker shows the language in use after a switch fails, where it kept the language that failed to load selected. It also renders from `binding.subscribe()`, so it follows a language the binding switches to, and keeps the latest of several quick picks selected while it loads.
- The docs say that the second `initializeBrowserI18n()` rejects with a `TypeError`, and that a start in a Web Worker without `syncDocument: false` rejects rather than throws.
- The translations guide's test checks the tags `rich()` reads as well as the syntax, and no longer says it checks every message.
- The localized-URL guide skips the paths you serve as files, where it skipped every path ending in an extension, such as the page `/blog/node.js`, and its static-site redirect builder skips a private-use locale, such as `x-pirate`, where it threw.
