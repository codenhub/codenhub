# 0.1.0

## Added

- **`storeErrors`**, end-user messages for every `store.*` code, ready to register in an `@codenhub/error` registry, and the `StoreErrorCode` type. See [Validation and failures](../core-stores.md#validation-and-failures).
- **`store.clear_unsupported`.** `clear()` on a driver without a `clear` method reports this code and leaves the stored value in place, instead of doing nothing silently.
- Guides for when the package fits and when a database does, which values survive each driver, Cloudflare KV limits, validation, custom drivers, and every failure the store reports.

## Changed

- **Breaking.** Error codes are namespaced: `storage-read-failed` is now `store.read_failed`, and likewise `store.write_failed`, `store.clear_failed`, `store.parse_failed`, and `store.validation_failed`. Update any code that compares `error.code`.
- **Breaking.** `localStorageDriver(storageKey, onError)` no longer takes `onError`. Pass `onError` to `createStore` instead; it is now the only place failures are reported.
- **Breaking.** When the driver fails to read, `patch`, `setItem`, and `removeItem` report `store.read_failed`, write nothing, and return the initial state. They used to write the initial state plus the change, which erased every other stored field. Unparsable or invalid stored values are still replaced.
- **Breaking.** Node.js 24 or newer is required.
- An exception thrown by `onError` now reaches the caller, and the callback is called once. It used to be caught, and could be called twice.
- **Breaking.** The Node JSON file drivers throw during store creation when a second storage key binds to a file already bound to another key in the process. The file holds one record, so the two stores used to overwrite each other.
- `createAsyncStore` copies the value given to `set`, `patch`, or `setItem` when called, so changing the object afterwards no longer changes what is written. A value that cannot be copied rejects the returned promise.

## Fixed

- The Node JSON file drivers write to a temporary file and rename it into place, so a crash or a full disk no longer leaves a half-written file in place of the previous value.
- An empty `storageKey` works with the localStorage and Cloudflare drivers. It used to fail every operation as if no key had been bound.
- `cloudflareDoDriver` accepts a Durable Object's `state.storage` as it is, whose `delete` resolves to a boolean.
- An error object the store reports is no longer changed, so a frozen error no longer causes a `TypeError`, and two stores that see the same error both report it.
