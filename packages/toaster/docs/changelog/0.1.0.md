# 0.1.0

First publish.

## Added

- `createToaster()` returns an independent instance with its own DOM, queues, timers, listeners, and token stylesheet.
- Semantic (`success`/`error`/`warning`/`info`), loading, and custom-content toast dispatchers, plus native `confirm`/`prompt`/`alert` dialogs, each returning a promise-based result.
- Overflow admission queues FIFO at capacity; a loader, a hovered toast, or a focused toast is protected from eviction, and a `maxVisible` lowered at runtime reconciles existing occupancy the same way.
- Toast and dialog colors, presentation (`.solid`/`.soft`/`.ghost`/`.edged`/`.edgeless`), and aesthetic material (clip, shadow, elevation) compose live against an optional `@codenhub/styles >=0.3.0` peer, with a generated standalone fallback when it isn't installed.
- Per-instance and per-call `ToastTokens` color overrides, an optional CSP `nonce` for the token stylesheet, and a sanitized custom-HTML content path alongside trusted DOM node content.
- `ToastHandle.update()` can also replace a toast's message/content, swap its icon, switch its severity `type` (e.g. turning a loading toast into a success toast), and change its duration or auto-dismiss setting -- not only tokens and classes.
- `ToasterConfig.labels` sets instance-level default text for the dismiss button and dialog buttons (confirm/cancel/submit/ok), for localization without repeating the same option on every dialog call; a per-call label still wins over it.
- Auto-dismiss now pauses while the browser tab is in the background, the same way hover and focus already pause it, so time nobody could have read the toast doesn't count against its duration.

## Fixed

- `destroy()` now settles every handle synchronously instead of leaving it in `"hiding"` until an exit animation nothing is left to see would have finished.
- A closed dialog's rendered content (e.g. a prompt's draft input value) is cleared immediately instead of lingering until the dialog is reused.
- Custom content that sanitization strips down to nothing (e.g. a script-only string) now throws the same "must not be empty" error a literally empty string would, instead of silently rendering a blank toast.
- The dismiss button uses logical CSS properties so it sits at the correct trailing edge in right-to-left layouts instead of always the physical right.
- A corner stack's default margin now floors at `env(safe-area-inset-*)`, so it no longer renders underneath a device notch or home indicator when no explicit `margin` is configured.
- A stack with more simultaneous toasts than fit the viewport (a short viewport, several toasts, or tall content) now scrolls internally instead of running off-screen with the extra toasts permanently unreachable.
- A toast's width no longer floors or ceilings past what a large configured `margin` leaves available on a narrow viewport; it shrinks (wrapping its text) instead of overflowing past the margin.
- Dismissing a toast whose own element currently holds keyboard focus now restores focus to whatever held it immediately before that toast rendered, instead of dropping it to `<body>`.
- The scrollable stack no longer renders its own platform scrollbar track next to the toasts; scrolling (wheel, touch, and the scroll-to-reveal-newest behavior) still works with the chrome hidden.
- A toast anchored to a right-aligned position (`top-right`/`bottom-right`) now stays flush against that edge instead of drifting toward the left as a wider sibling joins the stack and grows its width.
- Adding a toast to a stack that already has one visible no longer clips or snaps an existing toast partway through the push animation; the push now accounts for the new toast's real, final height instead of the still-empty shell it briefly has before its content is populated.
