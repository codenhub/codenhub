# Issues

Every operation on untrusted input returns a result instead of throwing. This page describes what a failed result holds, lists every code the package can return, and says which mistakes throw.

## The failed result

```ts
// What the client returned for a callback whose ID token had expired and named another audience.
const result = {
  ok: false,
  error: {
    issues: [
      { code: "invalid_id_token", path: ["id_token", "payload", "exp"], params: { jwtCode: "expired" } },
      { code: "invalid_id_token", path: ["id_token", "payload", "aud"], params: { jwtCode: "wrong_audience" } },
    ],
  },
};
```

`error.issues` is never empty, and its type says so, so `result.error.issues[0]` is an issue and not `undefined`. Issues are listed in the order the checks ran. A check that stops at its first failure leaves one issue, and the claim checks of the ID token report every failing claim. The whole result is deeply frozen.

A failed `beginAuthorization` result also has a `redirect`: the response to return to the browser, or `null` when the app must render an error. See [Provider](provider.md#starting-beginauthorization).

## The issue

| Field    | Meaning                                                                                                                                                                                                                        |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `code`   | The stable category of the failure. Branch on it. The type is a union of string literals, and the list below is complete for this version.                                                                                     |
| `path`   | Where the failure is, when it concerns one place: `["callback", "state"]`, `["id_token", "payload", "exp"]`, `["response", "access_token"]`, `["client_id"]`. Omitted when it concerns the whole input or no particular place. |
| `params` | Facts that are never input values: the endpoint, a reason, an HTTP status, a limit, a `jwtCode`, or an OAuth code the provider sent. Omitted when there are none.                                                              |

An issue never holds a value taken from the input: no token, code, secret, verifier, claim value or response body. Where a provider sent an OAuth error, the issue carries the code only when it is one of the OAuth error codes the package knows, and `unknown` otherwise. A `params.status` is an HTTP status number, and never content.

There are no messages. A code is the whole answer. Map codes to text yourself, and prefer telling a client only "invalid request" when the client may be an attacker.

Three kinds of issue come from `@codenhub/jwt`, not this package. An `invalid_id_token` issue wraps a `@codenhub/jwt` issue: its `jwtCode` names the JWT check, and its `params` carry whatever that check reported, such as `{ limit: "length", maximum: 8192 }` for `too_large` or `{ claim: "exp" }` for `missing_claim`. The `path` is the JWT path with `"id_token"` in front.

## Client issues

These come from `discover`, the client's `callback`, `refresh`, `userinfo` and `revoke`, and their token, userinfo and revocation requests.

| Code                     | Where it comes from                                                                                                                                          | `path`                                                                                                                                                                                                                                                          | `params`                                                                                                                                                                                                                                                                                                                                     |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `request_failed`         | `discover`, the token request, the userinfo request and the revocation request.                                                                              | None.                                                                                                                                                                                                                                                           | `endpoint`: `discovery`, `token`, `userinfo` or `revocation`. `reason`: `timeout`, `network`, `status`, `too_large`, `content_type` or `malformed`. `status`, the HTTP status, for `reason` of `status`.                                                                                                                                     |
| `invalid_metadata`       | `discover`, for a discovery document.                                                                                                                        | `["metadata", <member>]` for a listed member that is missing, invalid or an accessor. `["metadata"]` when the document is not an object, when an unlisted member is an accessor, or when the document cannot be copied (too deep, too many containers, cyclic). | None.                                                                                                                                                                                                                                                                                                                                        |
| `issuer_mismatch`        | `discover`, when the document's `issuer` is not the one requested.                                                                                           | `["metadata", "issuer"]`.                                                                                                                                                                                                                                       | None.                                                                                                                                                                                                                                                                                                                                        |
| `invalid_token_response` | The token request, for a `200` response that is not a valid token response.                                                                                  | `["response", <member>]`, such as `["response", "access_token"]`, or `["response", "id_token"]` when the ID token is missing.                                                                                                                                   | None.                                                                                                                                                                                                                                                                                                                                        |

| `invalid_callback`       | `callback`, for a URL, a parameter set, a missing `state` or a missing `code`.                                                                               | `["callback"]`, `["callback", "state"]` or `["callback", "code"]`.                                                                                                                                                                                              | `reason`, on `["callback"]`: `duplicate`, `too_many`, `too_long` or `malformed` (a percent-escape that is not valid UTF-8).                                                                                                                                                                                                                  |

| `azp_mismatch`           | The ID token check, when `azp` is not this client, or is missing when `aud` lists several audiences.                                                         | `["id_token", "payload", "azp"]`.                                                                                                                                                                                                                               | None.                                                                                                                                                                                                                                                                                                                                        |
| `at_hash_mismatch`       | The ID token check, when `at_hash` does not match the access token.                                                                                          | `["id_token", "payload", "at_hash"]`.                                                                                                                                                                                                                           | None.                                                                                                                                                                                                                                                                                                                                        |
| `auth_time_missing`      | The ID token check, when `maxAge` was requested and `auth_time` is absent.                                                                                   | `["id_token", "payload", "auth_time"]`.                                                                                                                                                                                                                         | None.                                                                                                                                                                                                                                                                                                                                        |

| `subject_mismatch`       | `refresh`, when a new ID token's `sub` is not the subject given. `userinfo`, when the response's `sub` is not the subject given.                             | `["id_token", "payload", "sub"]` for refresh, `["userinfo", "sub"]` for userinfo.                                                                                                                                                                               | None.                                                                                                                                                                                                                                                                                                                                        |

The `request_failed` issue for a redirect is browser-specific. In a browser, the client does not follow a redirect from a provider endpoint, and the response it gets is opaque, so the issue has `params.reason` of `status` and `params.status` of `0`. In Node.js and workerd, `params.status` is the redirect's own status.

### What the app does with a client issue

The client reports what went wrong and never tells the user why. The app decides what the user sees. The table gives the usual action for each code.

| Code                                                                     | What the app does                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `request_failed`                                                         | Discovery, userinfo and revocation: provider or network trouble. Offer the user a retry; the request is safe to repeat. The token request: offer the user a retry that starts sign-in again, since a code or refresh token may have been spent.                                                                                                                                                                                |
| `invalid_metadata`, `issuer_mismatch`                                    | A configuration or provider fault. Log it for operators and stop. A retry fetches the same document, so do not loop.                                                                                                                                                                                                                                                                                                           |
| `invalid_token_response`                                                 | Provider trouble. Offer the user a retry that starts sign-in again.                                                                                                                                                                                                                                                                                                                                                            |
| `invalid_userinfo`                                                       | Provider trouble. Treat the profile as unavailable, and show a retry.                                                                                                                                                                                                                                                                                                                                                          |
| `provider_error`                                                         | Branch on `params.error`. `access_denied`: the user declined, so say so. `invalid_client`: a configuration fault; stop and fix the credentials. `invalid_grant` at the token endpoint: a generic grant rejection, such as a spent or expired code or refresh token, a wrong PKCE verifier, or a redirect URI or client that does not match; start sign-in again. Any other code, or `unknown`: provider trouble; show a retry. |
| `invalid_callback`                                                       | The callback URL is malformed or incomplete. Start sign-in again. Do not retry the same URL.                                                                                                                                                                                                                                                                                                                                   |
| `state_mismatch`, `iss_mismatch`                                         | The response does not belong to this request. Discard `pending`, and start sign-in again.                                                                                                                                                                                                                                                                                                                                      |
| `invalid_id_token`, `nonce_mismatch`, `azp_mismatch`, `at_hash_mismatch` | Do not sign the user in, and drop the tokens from this response. Start sign-in again. For `invalid_id_token`, log `params.jwtCode` for operators, since it names the check that failed.                                                                                                                                                                                                                                        |
| `auth_time_missing`                                                      | Do not sign the user in. The provider did not send `auth_time` for a `maxAge` request. Start sign-in again.                                                                                                                                                                                                                                                                                                                    |
| `auth_too_old`                                                           | Do not sign the user in. Start sign-in again with `prompt: ["login"]`, so the user authenticates again.                                                                                                                                                                                                                                                                                                                        |
| `subject_mismatch`                                                       | The response is about another user. Drop the session, do not show the profile, and sign the user in again.                                                                                                                                                                                                                                                                                                                     |

The OAuth codes a provider can send as `provider_error`'s `params.error` are the 22 codes the package knows, or `unknown` for any other value: `invalid_request`, `unauthorized_client`, `access_denied`, `unsupported_response_type`, `invalid_scope`, `server_error`, `temporarily_unavailable`, `invalid_client`, `invalid_grant`, `unsupported_grant_type`, `unsupported_token_type` (RFC 7009 §2.2.1), `invalid_token`, `insufficient_scope`, `interaction_required`, `login_required`, `account_selection_required`, `consent_required`, `invalid_request_uri`, `invalid_request_object`, `request_not_supported`, `request_uri_not_supported` and `registration_not_supported`. The provider's own description is never returned.

## Provider issues

These come from `beginAuthorization`, `completeAuthorization` and `endSession`. The token and userinfo endpoints do not return issues. They answer with the OAuth error responses described in [Provider](provider.md#the-token-endpoint), which carry only the code.

Seven of the OAuth codes are issue codes, and only in this table: `invalid_request`, `unauthorized_client`, `unsupported_response_type`, `invalid_scope`, `request_not_supported`, `request_uri_not_supported` and `registration_not_supported`. No other OAuth code is an issue code. A denial that `completeAuthorization` returns is a redirect carrying an `error` parameter, such as `access_denied`, which the client receives in its callback, not an issue.

| Code                                                                               | Where it comes from                                                                                                                                                                             | `path`                                                                                                                                                | `params`                                                                                                                                          |
| ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `invalid_request`                                                                  | `beginAuthorization`, for a URL, a body, a parameter set, or a missing or malformed parameter.                                                                                                  | `["client_id"]`, `["response_type"]`, `["response_mode"]`, `["code_challenge"]`, `["code_challenge_method"]`, `["prompt"]` or `["max_age"]`, or none. | `reason`, for a parameter set that does not parse: `duplicate`, `too_many`, `too_long` or `malformed` (a percent-escape that is not valid UTF-8). |
| `unknown_client`                                                                   | `beginAuthorization`, when no client has the `client_id`. Always rendered.                                                                                                                      | None.                                                                                                                                                 | None.                                                                                                                                             |
| `invalid_redirect_uri`                                                             | `beginAuthorization`, when `redirect_uri` is missing or not registered. Always rendered.                                                                                                        | None.                                                                                                                                                 | None.                                                                                                                                             |
| `unauthorized_client`                                                              | `beginAuthorization`, when the client is registered without `authorization_code`. Redirected, once the client and redirect URI are verified.                                                    | None.                                                                                                                                                 | None.                                                                                                                                             |
| `unsupported_response_type`                                                        | `beginAuthorization`, when `response_type` is not `code`. Redirected.                                                                                                                           | None.                                                                                                                                                 | None.                                                                                                                                             |
| `invalid_scope`                                                                    | `beginAuthorization`, when `scope` lacks `openid`, or names a scope the provider or the client does not have. Redirected.                                                                       | None.                                                                                                                                                 | None.                                                                                                                                             |
| `request_not_supported`, `request_uri_not_supported`, `registration_not_supported` | `beginAuthorization`, for a `request`, `request_uri` or `registration` parameter. Redirected.                                                                                                   | None.                                                                                                                                                 | None.                                                                                                                                             |
| `interaction_not_found`                                                            | `completeAuthorization`, when the id is empty or unknown, was completed, or has expired. Not redirected.                                                                                        | None.                                                                                                                                                 | None.                                                                                                                                             |
| `invalid_request`                                                                  | `endSession`, for a malformed request: a method or media type the endpoint does not accept, an oversized URL or request body, an unreadable body, or a parameter that does not parse. Rendered. | `["id_token_hint"]` when a verified hint was issued to another client than `client_id`; otherwise none.                                               | `reason` for a parameter that does not parse: `duplicate`, `too_many`, `too_long` or `malformed`.                                                 |
| `unknown_client`                                                                   | `endSession`, when `client_id` names no client. Rendered.                                                                                                                                       | None.                                                                                                                                                 | None.                                                                                                                                             |
| `invalid_redirect_uri`                                                             | `endSession`, when `post_logout_redirect_uri` is not one of the client's `postLogoutRedirectUris`, or no client is known to check it against. Rendered.                                         | `["post_logout_redirect_uri"]`.                                                                                                                       | None.                                                                                                                                             |

Whether a `beginAuthorization` code redirects depends on whether the client and its redirect URI were verified first. The codes checked after that verification redirect, and the others are rendered. The `endSession` codes are always rendered.

## What throws

Some mistakes throw instead of returning a result. They are bugs in the code that calls the package, and the message names the option or member at fault, never its value.

- **`TypeError` from a synchronous call.** `createClient` and `createProvider` throw when an option is invalid, so a misconfigured client or provider never starts. `createClient` throws, for example, for a non-`https` issuer, a `clientId` that is empty, a `redirectUri` with a fragment, an `auth.method` the provider does not advertise, or a `client_secret_jwt` or `private_key_jwt` key whose `alg` the provider does not list in `token_endpoint_auth_signing_alg_values_supported`. `client.endSessionUrl` returns a URL rather than a promise, so it throws too: when the metadata has no `end_session_endpoint`, when an option is invalid, or when the URL is longer than 8192 characters. `createProvider` throws when `onDiagnostic` is given and is not a function, or when `accessToken` is not `{ format: "opaque" }` or a `{ format: "jwt", audience }` with a valid `audience`.
- **`TypeError` from an asynchronous call.** Every other method that takes an options or outcome object rejects with `TypeError` rather than throwing. These are `discover` for its arguments, `client.authorize`, `client.callback`, `client.refresh`, `client.userinfo`, `client.revoke`, `client.clientCredentials`, `provider.completeAuthorization`, and `hashClientSecret`. Some of them reject for more:
  - `client.authorize` rejects when a `loginHint` or a `uiLocales` entry is not well-formed Unicode, and when the encoded authorization URL is longer than 8192 characters.
  - `client.userinfo` rejects when the metadata has no `userinfo_endpoint`, and `client.revoke` when it has no `revocation_endpoint`.
  - `client.clientCredentials` rejects when the client authenticates with `none`, or when the metadata lists `grant_types_supported` without `client_credentials`.
- **`TypeError` from the store or the callback.** A malformed client record from `findClient` is a `TypeError`: for example one whose redirect URI has a fragment, whose `grantTypes` repeats a value, whose `postLogoutRedirectUris` breaks the redirect URI rules, or that gives `client_credentials` to a client with `auth.method` `none`. `handle`, `beginAuthorization` and `endSession` reject with it when a request uses the record. A `claims` callback that resolves to something other than an object is a `TypeError` too. Both reject the request that reached them.
- **`TypeError` for a request whose body was already read.** `beginAuthorization`, `endSession`, and `handle` for a token or revocation request reject with it for a `POST` whose body another part of the app read first, such as middleware that parsed the form. It is a bug in the app's routing, not something the client sent.
- **Store and callback failures.** A store method that throws or rejects, and a `claims` callback that throws or rejects, reject the call that reached them. They are not results. See [Store](store.md#errors).

Hostile input never produces a `TypeError`. A token that does not parse, a discovery document with a missing member, and a callback with no `state` each produce an issue, and no operation throws because of them.
