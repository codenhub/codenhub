# Hostile input

This page answers one question for each input that can come from the other side: what does it get? It covers the provider's endpoints (authorization, end-session, token, userinfo and revocation), `authenticate` for the app's own API, and the client's callback, token, userinfo and discovery requests. For each input it states the exact outcome, so you can test your deployment against it.

Two results are used throughout. A **result** is the failed value `{ ok: false, error: { issues } }`, described in [Issues](errors.md). A **response** is the HTTP answer the provider sends. A `TypeError` is never an outcome of hostile input, because the package treats the input as data.

## Provider: the authorization endpoint

These inputs arrive at `beginAuthorization` and `completeAuthorization`. "Render" means `redirect` is `null` and the app shows its own error. "Redirect" means the client is sent back, with `error`, `state` and `iss`.

| Input                                                                                                                                                                         | Outcome                                                                                                 |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| A URL longer than 8192 characters                                                                                                                                             | Render, `invalid_request`.                                                                              |
| A method other than `GET` or `POST`, or a `POST` without a form body                                                                                                          | Render, `invalid_request`.                                                                              |
| A duplicated parameter other than `resource`, more than 32 parameters, or one longer than 4096 characters                                                                     | Render, `invalid_request`, with `params.reason` of `duplicate`, `too_many` or `too_long`.               |
| A percent-escape that is not valid UTF-8, such as `%E9` or `%FF`. A malformed escape such as `%zz` stays literal text, as the URL standard says.                              | Render, `invalid_request`, with `params.reason` of `malformed`.                                         |
| No `client_id`                                                                                                                                                                | Render, `invalid_request`, path `["client_id"]`.                                                        |
| An unknown `client_id`                                                                                                                                                        | Render, `unknown_client`. Nothing is redirected, since no client was verified.                          |
| A `redirect_uri` that is not one of the client's registered URIs byte for byte: a trailing slash, a different case, a port, an added query, a fragment, or an encoded variant | Render, `invalid_redirect_uri`. Nothing is normalized, so a near miss never reaches a redirect.         |
| `request`, `request_uri` or `registration`                                                                                                                                    | Redirect, `request_not_supported`, `request_uri_not_supported` or `registration_not_supported`.         |
| `response_type` missing                                                                                                                                                       | Redirect, `invalid_request`, path `["response_type"]`.                                                  |
| `response_type` of `token`, `id_token`, or a hybrid value                                                                                                                     | Redirect, `unsupported_response_type`. Only the code flow exists, so no token goes through the browser. |
| `response_mode` other than `query`                                                                                                                                            | Redirect, `invalid_request`, path `["response_mode"]`.                                                  |
| `scope` missing `openid`, or missing altogether, or naming a scope the client's record does not list or that is not a scope token                                             | Redirect, `invalid_scope`.                                                                              |
| A `resource` that is not one of the client's `resources` byte for byte, including one with a fragment, a relative one, or one the client has no list for                      | Redirect, `invalid_target`. A repeated `resource` is allowed and counts once.                           |
| A `code_challenge` that is missing (unless the client has `requirePkce: false`) or is not the shape of an S256 challenge                                                      | Redirect, `invalid_request`, path `["code_challenge"]`.                                                 |
| A `code_challenge_method` that is missing, `plain`, or anything but `S256`; or one sent with no challenge                                                                     | Redirect, `invalid_request`, path `["code_challenge_method"]`. `plain` is never accepted.               |
| No `code_challenge` and no `nonce`, from a client with `requirePkce: false`                                                                                                   | Redirect, `invalid_request`, path `["nonce"]`.                                                          |
| `prompt` with an unknown value, or `none` with another value                                                                                                                  | Redirect, `invalid_request`, path `["prompt"]`.                                                         |
| `max_age` that is negative, has a sign, a decimal point, a space, or more than nine digits                                                                                    | Redirect, `invalid_request`, path `["max_age"]`.                                                        |
| An interaction id that is forged, empty, reused, or expired                                                                                                                   | `completeAuthorization` returns `interaction_not_found`, with no redirect.                              |
| An app outcome that grants scopes the request did not ask for, or grants no `openid`                                                                                          | `completeAuthorization` throws `TypeError`, and the interaction is already consumed.                    |

## Provider: the end-session endpoint

The end-session endpoint never redirects a failed request, so the app renders each row below, except where it says otherwise. A redirect goes only to a `post_logout_redirect_uri` the client registered.

| Input                                                                                                                                                                                    | Outcome                                                                                                                                     |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| A method or media type the endpoint does not accept, or a URL longer than 8192 characters                                                                                                | Render, `invalid_request`.                                                                                                                  |
| A duplicated, too many, too long or malformed parameter, or a percent-escape that is not valid UTF-8                                                                                     | Render, `invalid_request`, with `params.reason` of `duplicate`, `too_many`, `too_long` or `malformed`.                                      |
| An unknown `client_id`                                                                                                                                                                   | Render, `unknown_client`.                                                                                                                   |
| An `id_token_hint` that verifies, issued to a client other than `client_id`                                                                                                              | Render, `invalid_request`, path `["id_token_hint"]`.                                                                                        |
| An expired `id_token_hint` that is otherwise valid                                                                                                                                       | Accepted as an unexpired one is: it names the user and the client, and it is refused when it was issued to another client than `client_id`. |
| A forged or foreign `id_token_hint`, one issued in the future, a JWT access token, or a hint with several audiences and no `azp` among them                                              | Ignored. The result has no `subject` and no failure, so the app asks the user to confirm the logout.                                        |
| A `post_logout_redirect_uri` that is not, byte for byte, one of the client's `postLogoutRedirectUris`: a trailing slash, a different case, a port, an added query, or an encoded variant | Render, `invalid_redirect_uri`, path `["post_logout_redirect_uri"]`. Nothing is redirected.                                                 |
| A `post_logout_redirect_uri` when no client is known, from `client_id` or from the hint                                                                                                  | Render, `invalid_redirect_uri`. Nothing is redirected.                                                                                      |

## Provider: the token endpoint

| Input                                                                                                                                                                                           | Outcome                                                                                                                          |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| A method other than `POST`                                                                                                                                                                      | `405`, with `Allow: POST, OPTIONS`.                                                                                              |
| A `Content-Type` other than `application/x-www-form-urlencoded`, with `charset=utf-8` allowed, quoted or not, in any letter case                                                                | `400`, `invalid_request`.                                                                                                        |
| A body larger than 16384 bytes. A declared `Content-Length` above the cap is refused without reading the body.                                                                                  | `400`, `invalid_request`. The body is cancelled as soon as it passes the cap, even when the declared length lied.                |
| A body that is not valid UTF-8, a percent-escape that is not valid UTF-8 (such as `%E9`), or a duplicated, too-long or excess parameter                                                         | `400`, `invalid_request`.                                                                                                        |
| Credentials presented two ways at once (`Authorization`, `client_secret` and `client_assertion` together)                                                                                       | `400`, `invalid_request`.                                                                                                        |
| Any `Authorization` header that does not authenticate the client: a malformed Basic header, another scheme such as `Bearer`, or an empty one                                                    | `401`, `invalid_client`, with `WWW-Authenticate: Basic realm="token"`. A failed check on a Basic header gets the same challenge. |
| A body `client_id` that differs from the Basic header's                                                                                                                                         | `400`, `invalid_request`, without `WWW-Authenticate`.                                                                            |
| An unknown client, a wrong secret, a wrong key, or a method the client did not register                                                                                                         | `401`, `invalid_client`. The cases are not told apart, so an attacker cannot learn which clients exist.                          |
| A client assertion with a wrong signature, a wrong `aud`, an expired `exp`, an `exp` more than 360 seconds ahead (300 plus the 60-second tolerance), no `jti`, or a `sub` other than the client | `401`, `invalid_client`.                                                                                                         |
| A `grant_type` that is missing, or is neither `authorization_code`, `refresh_token` nor `client_credentials`                                                                                    | `400`, `invalid_request` when missing, or `unsupported_grant_type`.                                                              |
| A code verifier that is not 43 to 128 unreserved characters                                                                                                                                     | `400`, `invalid_grant`. The code is not spent.                                                                                   |
| A code presented a second time                                                                                                                                                                  | `400`, `invalid_grant`. The grant the code belongs to is revoked, so its access and refresh tokens stop working.                 |
| A correct code with a wrong verifier, or with a different `redirect_uri`, or by another client, or after it expires                                                                             | `400`, `invalid_grant`. The code is spent, so a second attempt is a replay.                                                      |
| A `code_verifier` sent for a code issued without a challenge, from a client with `requirePkce: false` (a downgrade attempt)                                                                     | `400`, `invalid_grant`. The code is spent.                                                                                       |
| An unknown code, or one that has been purged                                                                                                                                                    | `400`, `invalid_grant`.                                                                                                          |
| A refresh token presented a second time                                                                                                                                                         | `400`, `invalid_grant`. The family is revoked, so every token issued from it stops working.                                      |
| A refresh token that is unknown, or revoked                                                                                                                                                     | `400`, `invalid_grant`. It is not spent, since there is nothing to spend.                                                        |
| A refresh token that is expired, or presented by another client                                                                                                                                 | `400`, `invalid_grant`. The token is spent.                                                                                      |
| A refresh `scope` that names a scope the client's record does not list                                                                                                                          | `400`, `invalid_scope`. The token is not spent.                                                                                  |
| A refresh `scope` that names a scope the family does not hold                                                                                                                                   | `400`, `invalid_scope`. The token is spent, and no new refresh token is issued.                                                  |
| A refresh that the app's `onRefresh` refuses by answering `false`                                                                                                                               | `400`, `invalid_grant`. The token is spent and the family is revoked.                                                            |
| An access token sent as a `refresh_token`                                                                                                                                                       | `400`, `invalid_grant`. Refresh tokens are looked up in their own table.                                                         |
| A `client_credentials` request that asks for `openid` or `offline_access`, or for a scope the client does not have                                                                              | `400`, `invalid_scope`. No token is issued.                                                                                      |
| A `grant_type` the client is not registered for: `client_credentials` from a client without it, or `authorization_code` or `refresh_token` from a client without `authorization_code`           | `400`, `unauthorized_client`. Nothing is spent or issued.                                                                        |
| A `resource` that is not one of the client's `resources`, at any grant                                                                                                                          | `400`, `invalid_target`. The code or refresh token is not spent.                                                                 |
| A `resource` the client may name but the grant does not cover, at the code exchange or a refresh                                                                                                | `400`, `invalid_target`. The code or refresh token is spent, and no new refresh token is issued.                                 |

## Provider: userinfo

| Input                                                   | Outcome                                                                                                 |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| No `Authorization` header                               | `401`, `WWW-Authenticate: Bearer`, with no error code.                                                  |
| A header that is not a well-formed `Bearer` credential  | `400`, `WWW-Authenticate: Bearer error="invalid_request"`.                                              |
| A token in the query or the body, and no header         | Ignored. The response is the same as for no header.                                                     |
| An ID token presented as an access token                | `401`, `WWW-Authenticate: Bearer error="invalid_token"`. ID tokens are never in the access token table. |
| A refresh token presented as an access token            | `401`, `invalid_token`, for the same reason.                                                            |
| An expired access token, or one whose grant was revoked | `401`, `invalid_token`.                                                                                 |

## Provider: authenticate

| Input                                                                              | Outcome                                                                                                                |
| ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| No `Authorization` header, or a token only in the query or the body                | Failure `access_token_missing`: `401`, `WWW-Authenticate: Bearer`, with no error code.                                 |
| A header that is not a well-formed `Bearer` credential                             | Failure `access_token_malformed`: `400`, `error="invalid_request"`.                                                    |
| An oversized token                                                                 | Not found, so `access_token_unknown`: `401`, `error="invalid_token"`. The request body is never read.                  |
| An ID token, a refresh token or a code presented as an access token                | `access_token_unknown`, `401`, `invalid_token`. Only access tokens are looked up.                                      |
| An expired access token, or one whose grant was revoked                            | `access_token_expired` or `access_token_unknown`, `401`, `invalid_token`.                                              |
| An access token for another resource server, or for none, when `audience` is given | `access_token_audience_mismatch`, `401`, `invalid_token`. Checked before the scopes, so the challenge names none.      |
| An access token without one of the required `scopes`                               | `access_token_scope_insufficient`, `403`, `error="insufficient_scope"` and the required scopes, each once, in `scope`. |
| Malformed `options` from the app                                                   | Rejects with `TypeError` before the store is read. No request input can cause it.                                      |

No outcome is reported to `onDiagnostic`, and no response carries CORS headers.

## Provider: revocation

| Input                                                                            | Outcome                                                                                                                             |
| -------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| A method other than `POST` or `OPTIONS`                                          | `405`, with `Allow: POST, OPTIONS`.                                                                                                 |
| A content type, body, parameter or client authentication failure                 | The same answer as the token endpoint: `400 invalid_request`, or `401 invalid_client` with the challenge rules above.               |
| No `token`, or an empty one                                                      | `400`, `invalid_request`.                                                                                                           |
| A token the store does not find: unknown, purged, or of an already revoked grant | `200`, with nothing revoked.                                                                                                        |
| An access or refresh token the store holds, live or expired                      | `200`, and its grant is revoked. The provider does not check expiry here, so an expired token still in the store revokes its grant. |
| A refresh token already spent, presented again                                   | `200`, and its grant is revoked, as a replay.                                                                                       |
| A token issued to another client                                                 | `400`, `invalid_request`. An access token is left alone. A refresh token is spent and its grant is revoked.                         |

## Provider: back-channel logout

`provider.backchannelLogout` is a method the app calls, not an endpoint, so none of its input is hostile: a wrong call is the app's bug and throws `TypeError`. What it handles is the client's record, and what it produces is a request the app's server sends to the client.

| Input                                                                                                                  | Outcome                                                                                                                 |
| ---------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| A client the store does not know, or one with no `backchannelLogout`                                                   | `null`. Nothing is built, so nothing is sent.                                                                           |
| Neither `subject` nor `sessionId`, an empty or non-string one, or no `sessionId` for a client with `sessionRequired`   | `TypeError`, before any token is signed. The message names the member, never its value.                                 |
| A record whose `backchannelLogout.uri` is not an absolute `https` URL of visible ASCII without fragment or credentials | `TypeError`, as for any malformed record. A plain `http` URI is refused, since the token would cross the network clear. |
| The logout token presented where an ID token is expected                                                               | Refused: its `typ` is `logout+jwt`, and an ID token check requires `JWT`.                                               |
| An ID token presented where a logout token is expected                                                                 | Refused for the same reason, in the other direction.                                                                    |
| A logout token for a client other than the one it names in `aud`                                                       | Refused by the audience check of whoever verifies it. The token names only the client it was built for.                 |

The token lives for 120 seconds and carries a random `jti`, so a captured one is useless soon, and a client that remembers `jti` values refuses a replay within that time. The provider remembers nothing, and each call signs a new token.

## What never leaks

A result, a response and a `TypeError` message reveal no input value, by construction:

- Every issue's `path` names a place, such as a claim or a header member. Its `params` hold fixed vocabulary, numbers such as a limit or an HTTP status, and facts from the configuration. Never a token, code, verifier, secret, claim value or response body.
- The token endpoint's error responses hold only the OAuth code. They carry no `error_description`, so no input is echoed.
- A provider error that reaches the client is narrowed to a known OAuth code, or `unknown`, so the provider's text never becomes an issue.
- The store sees digests of every code, token and interaction id. A client secret is stored only as its SHA-256 digest, one per secret the client may use, with one exception: a `client_secret_jwt` client's record holds its HMAC key itself, because the provider needs that key to verify assertions. The store must protect it as a credential. See [Store](store.md#client-records). The PKCE verifier is never stored, only the challenge.
- `onDiagnostic` never receives a request value. Its `clientId` comes from the store, never from a request alone, and the other members are an endpoint, a reason from a fixed list and a status. See [Provider](provider.md#diagnostics).
- The userinfo response holds only the claims the granted scopes release, taken from the callback's own data properties, and the `sub` the token was issued to.
- `TypeError` messages name the option or the record member that is wrong, and never its value.

### Constant-time comparisons

The package compares the `state` and the client secret's digest (against every digest the client has, without stopping at the first match), the PKCE challenge, and the ID token's `nonce` and `at_hash`, in constant time. Equal-length values are compared without leaking, through timing, where they first differ. A value of another length is refused at once, so the length of a secret is not hidden. Lengths are not treated as secret.

## What the package does not defend

These are outside its scope. Each one is either the app's job or a known gap.

- **Rate limiting.** No endpoint limits how many requests a client or an IP sends. Limit the login, the token and the userinfo endpoints at the edge or in the app.
- **The app's session and cookies.** Where `pending` and the interaction id live, CSRF on the login and consent pages, session fixation, and phishing of the login page are the app's to get right. The package gives the values; it does not protect the place they are kept.
- **Store atomicity.** A store that does not satisfy the contract in [Store](store.md) breaks single use for codes and refresh tokens. The package cannot detect that, and it does not try.
- **A client with `requirePkce: false` is trusted to check the `nonce`.** Without PKCE, the ID token's `nonce` is what stops an attacker from injecting a stolen code into the client's session (OAuth 2.1 §7.5.1.1, RFC 9700 §2.1.1). The provider makes such a client send a `nonce` and puts it in the ID token, but cannot check that the client compares it. Turn it off only for a confidential client you know does, and never for a public one, which the provider refuses.
- **A client with `idTokenClaims: true` receives personal data in a token it may pass around.** The claims the granted scopes release are placed in every ID token of that client, where a client that logs the token, stores it in a cookie, or forwards it to another service exposes them. The provider cannot see what the client does with its tokens. Turn it on only for a relying party that reads nothing else, and give it only the scopes it needs. The provider's own claims are never replaceable by the callback's, so the option cannot forge a `nonce`, `sid` or any other protocol claim.
- **Assertion replay.** A client assertion's `jti` is required but not remembered, so a captured assertion can be replayed while it is accepted: an `exp` at most 300 seconds ahead of the provider's clock, plus 60 seconds of tolerance. This is by design. A replayed assertion alone gets nothing, since a code also needs its PKCE verifier and a refresh token is single use. Remembering every `jti` would cost each store a table and a write on every token request.
- **Revocation reaches only what the provider sees.** The revocation endpoint ends a grant, but the package has no introspection endpoint. A resource server sees a revocation only by calling userinfo, or by `authenticate` when the app serves it over the provider's store. An access token it accepts otherwise keeps working until `ttl.accessToken` seconds have passed.
- **Claims the app adds to JWT access tokens.** `accessTokenClaims` cannot replace or add a claim the provider sets, but the provider cannot tell what the claims it adds reveal: a JWT access token is readable by the client and by anything the client passes it to. A role it carries holds until the token expires, even after the app removes it.
- **JWT access tokens and revocation.** With `accessToken: { format: "jwt" }`, the provider revokes a token at once, but a resource server that verifies it offline sees a revocation only when the token expires. Keep `ttl.accessToken` short, as [JWT access tokens](provider.md#jwt-access-tokens) advises.
- **Sender-constrained tokens.** Access tokens are bearer tokens. DPoP and mutual TLS are not supported.
- **How the user authenticates.** The package records what the app says about the login in `authTime`, `amr` and `acr`. It does not verify them, and an `amr` of `["pwd"]` is what the app claims, not a check. The same holds for `sessionId`: the provider copies it into the `sid` claim without interpreting it, so a client sees whatever the app chose, and it should not be a secret.
- **Where a logout request goes.** `backchannelLogout` builds a request to the `uri` in a client's record, and the app's own server sends it. The package requires `https` and refuses credentials and fragments, but not an address on a private network: a client registered with `https://169.254.169.254/` or an internal host makes the app call it. When anyone but you registers clients, apply your own egress rules when you send, such as refusing private, loopback and link-local addresses after DNS resolution, and keep the request's `redirect: "manual"` so a redirect cannot reach one either. Timeouts, retries and logging of the outcome are the app's too.
- **Key management.** The package signs with the keys it is given. Storage of the private keys, the timing of rotation, and a compromised signing key are the app's. A key that leaks lets anyone forge ID tokens for that provider.
- **Redirect URI registration.** The app registers each client's URIs. The package matches them exactly and does not decide which are safe.
- **The provider's identity on the client side.** The client trusts discovery over `https`, the issuer match and the signatures from the provider's keys. It does not pin the keys or the endpoints beyond that.
